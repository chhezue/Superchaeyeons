# Core — 범위·우선순위 (단정 금지)

이슈·스펙의 **우선순위 라벨과 미확정 항목**을 다룰 때 지키는 규칙. 판단을 에이전트가 임의로 내리지 않는 것이 핵심이다.

이 저장소 고유의 릴리즈 사실(심사 게이트·릴리즈 축·도메인 일정 용어)은 `local-release.md` 같은 `local-` 접두사 규칙 파일이 담당한다.
> 채운 예: `examples/tripfit/tripfit-release.md`

코어 STOP: `core-guardrails.md` · 작업 순서: `core-workflow.md`

## ⛔ priority: must / could · 용어 (단정 금지)

> **적용 조건:** 이 절은 이슈에 `priority:` 라벨 체계를 운영하는 프로젝트에만 적용된다. `{{우선순위 SSOT}}`가 `(없음)`이면 **이 절 전체를 무시한다** — 라벨이 없는 저장소에서 must/could를 논하는 것 자체가 단정이다. 절은 지우지 않는다(`harness-map.md` 규칙 4와 같은 이유). 아래 `[미정]` 절은 슬롯과 무관하게 항상 적용된다.

**판단 기준 (작업 성격 기준, 2026-08-26 재정의):** 성능 개선·폴더/패키지 구조 정리·리팩터·최적화 = `priority: could`. 그 외 **기능 구현 자체·버그 수정은 전부** `priority: must`. 현재 어떤 이슈가 could인지는 `{{우선순위 SSOT}}`가 갖는다 — 이 파일에 이슈 번호를 적지 않는다.

**⛔ 에이전트가 스스로 must/could를 판단해 라벨을 부여·변경하지 않는다 — 반드시 사용자에게 먼저 확인.** 2026-08-26 사고 계기: 외부 저장소 미러링·외부 캘린더 동기화 방식 변경 이슈 두 건을 에이전트가 "기능 구현/신뢰성 우선"으로 자체 판단해 must로 분류했다가 사용자가 could로 정정했다 — "새 기능([Feat]) 태그가 붙어 있다"는 표면적 신호만으로 must를 단정하지 말고, 실제 작업 성격(안정성·효율 개선인지)을 봐야 한다. 신규 이슈 생성 시에도 동일 — priority 필드는 애매하면 사용자 확인 후 채운다.

| 용어 | 의미 | SSOT |
|------|------|------|
| **이슈 `## 완료 조건`** (구 `## Must Have`) | **그 이슈**를 끝내는 체크리스트. `priority: must`와 이름이 겹쳐 헷갈려서 개명함 | 해당 Feature/Bug Issue |
| **Must** | 기능 구현 자체·버그 수정 | 이슈의 `priority: must` 라벨 |
| **Could** | 성능 개선·폴더/패키지 구조 정리·리팩터·최적화 (MoSCoW Could have) | 이슈의 `priority: could` 라벨 |
| **스펙 `MVP: In scope`** | 제품 범위에 들어감 — **`priority: must`와 별개 축** (범위 vs 작업 성격) | 혼동 금지 |

**금지**

- 근거(라벨) 없이 이슈를 Must/Could라고 말함
- **사용자 확인 없이 priority 라벨을 부여·변경**(신규 이슈 포함)
- Milestone·`priority:` 라벨 없이 이슈 방치
- 이미 구현·머지된 기능을 문서가 stale하다는 이유로 `{{제품 범위}}` Out으로 방치 (실제 의존관계가 생기면 In Scope·Must로 재승격하고 문서를 amend — 2026-08 사고 계기)

## `[미정]` 항목 처리

기획·스펙·BR에 미확정 항목이 생기면 **해당 문서에 `[미정]` 표기만** 남긴다. 별도 중앙 트래커에 모으지 않는다.

- 기획이 확정되면 문서를 직접 amend하고 필요 시 별도 Feat로 구현한다.
- 중앙 트래커가 다시 필요하다고 판단되면 그때 사용자에게 새 이슈 생성 여부를 확인한다 (`core-workflow.md` "새 이슈·새 브랜치·새 PR 생성은 항상 먼저 확인" 절).

**금지:** `[미정]`을 묻지 않고 임의 확정해 구현·커밋 · 중앙 `[미정]` 트래커 이슈를 새로 만들거나 되살리기

중앙 트래커를 두지 않기로 한 경위는 `{{우선순위 SSOT}}`에 있다.
