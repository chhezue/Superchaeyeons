# 위험 명령 차단 훅 오탐 줄이기 — 작업 보고서

`deny-dangerous-bash.sh`가 따옴표·heredoc·검색어 안의 글자 때문에 막던 일을 없애고, 위험 명령을 6묶음으로 나눠 묶음마다 막을지 맡길지 고르게 했다. 이 저장소는 파일 대량 삭제 묶음만 맡기고, 루트·홈·현재 폴더 통째 삭제는 계속 막는다.

## 무엇을 했나

- `.claude/hooks/deny-dangerous-bash.sh` — 정규식 한 줄 대조를 python3 판정기로 바꿨다. 명령을 해석해 실행되는 부분만 대조하고, `bash -c`·`eval`·`ssh`·SQL 클라이언트 인자·`$(…)`·백틱·셸이 받는 heredoc·셸 파이프·런타임 코드의 셸 호출 줄은 다시 검사한다. 해석하지 못하면 원문 전체를 대조한다. 맨 위에 묶음 상수 6개(`BLOCK_*`)를 두었고, 차단 메시지에 걸린 묶음과 상수 이름이 나온다
- `.claude/settings.json` — 이 훅 등록에 `"onFailure": "block"`
- `scripts/hook-cases.txt` — 이 훅 케이스 56건 → 238건 (오탐 통과 · 놓침 차단 · 해석 실패 후퇴 · 다시 검사하는 자리 · 묶음 상수 · 바닥 규칙 · 리뷰 지적)
- 다른 훅의 python3 호출 — `deny-out-of-scope-write.sh` · `deny-unverified-completion.sh` · 씨앗 훅 3개(`local-deny-db-migration.sh` · `local-auto-format-java.sh` · `local-warn-breaking-change.sh`)도 `python3 -I -c`로. 작업 폴더에 `json.py`가 있으면 그것을 불러와 판정이 뒤집히던 문제다. `.claude/rules/README.md` "훅 공통 규약"에 이 규약을 적고, `scripts/test-hooks.sh`에 가짜 `json.py`를 둔 폴더에서 `deny-*` 훅을 돌리는 내장 시험을 넣었다(`-I`를 잠시 빼면 4개 모두 실패하는 것을 확인)
- 설치 절차 — `init-harness`가 새 프로젝트에 붙일 때 "폴더 통째 삭제를 훅이 막을까요?"를 묻고 `BLOCK_BULK_DELETE`를 고친다(권장 막기). `.claude/rules/README.md` "훅 상수와 짝"에 이 짝을 적었다
- 문서 — 스펙 Approved 전환과 결정 기록, `docs/harness/README.md` 현재동작 요약, `.claude/rules/README.md` 설명 줄 두 개, 루트 `README.md` 예시
