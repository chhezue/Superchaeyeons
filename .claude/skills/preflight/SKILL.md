# Preflight

**이 스킬이 기본 동작과 다른 단 하나:** "통과했을 것"을 말하지 않는다. 명령을 실제로 실행한 결과와 실행하지 못한 이유만 보고한다.

"테스트 통과했습니다", "이슈 완료했습니다" 같은 자기 보고를 그대로 믿지 않고 **기계적으로** 확인하는 스킬이다. `specify`가 "구현 전 스펙"을 강제하듯, 이 스킬은 "보고 전 검증"을 강제한다. `deny-unverified-completion.sh` 훅이 코드 수정 후 테스트 없는 완료 선언을 되돌리므로, 이 스킬을 건너뛰면 턴이 끝나지 않는다.

## When to Use

- **사전 모드:** G2 승인 직후, 구현 첫 줄을 쓰기 전 — "다 짜고 보니 테스트 환경이 안 돌아가서 검증 못 함"을 미리 차단한다
- **사후 모드:** 사용자에게 "완료", "테스트 통과", "이슈 완료"라고 보고하기 직전 · Approved 스펙 또는 이슈의 완료 기준을 체크할 때 · API 계약을 건드린 변경 직후
- `safe-refactor` 4단계(Verify)는 이 스킬을 그대로 쓴다 — 중복 정의하지 않는다

**생략 가능:** 오타·문서 전용·단일 로그 문구 같은 검증 대상이 없는 변경. 문서만 고친 턴은 훅도 발화하지 않는다.

## 사전 모드 (G2 직후)

1. `{{빌드 명령}}`·`{{테스트 명령}}`이 **현재 상태에서** 성공하는지 실행한다. `(없음)`이면 건너뛴다.
2. 실패하면 그 실패가 이번 작업 때문이 아님을 먼저 확정한다 — 기존 실패는 사용자에게 알리고, 고칠지 무시할지 결정받는다.
3. 외부 의존 환경(DB·큐·검색 엔진·외부 API)이 로컬에 없어 돌릴 수 없는 검증이 있으면 **지금** 목록으로 적는다. 이 목록이 사후 모드 "검증하지 못한 것"의 초안이다.

## 사후 모드 (완료 보고 전)

1. **테스트** — `{{테스트 명령}}` 실행(핵심 로직 변경 시 전체 스위트). 실패가 있으면 원인 해결 전에는 "통과"라고 보고하지 않는다.
2. **스펙·이슈 체크리스트 대조** — `{{스펙 저장소}}`의 Must Have 체크박스와 `gh issue view`의 완료 기준을 **실제 코드**와 대조한다. 스펙 문구만 보고 `[x]`로 단정하지 않는다(`core-guardrails.md` STOP §1.5).
3. **불변 조건** — G2에서 확정한 불변 조건(Invariant)마다 검증 방법을 실제로 돌린다 (`safe-refactor`·`specify` 스펙의 "불변 조건" 절).
4. **API 계약 변경 시** — 요청·응답 형태·에러 코드·경로가 바뀌었다면 **[플래그: API 계약 보호]** lang 팩 "API 계약 변경" 절을 기준으로 사유 트레일러 필요 여부를 재확인하고, 계약 diff 도구로 **의도한 diff만** 있는지 본다. 무손실 리팩터는 diff가 하나라도 나오면 실패다.
5. **레거시 재점검** — 이번 변경이 대체한 구 경로·상수·문서 '현행' 문구가 남아 있지 않은지 확인(STOP §2).
6. **문서 품질** — 새 문서·50줄 이상 고친 `.md`는 `doc-reviewer`(advisory). `scripts/check-doc-style.sh <파일>` 오류 0.
7. **[플래그: 스택 리뷰어]** — 스택 코드를 3파일 이상·API·DB 범위로 고쳤으면 lang 팩이 지정한 리뷰어 서브에이전트. 정적 검사가 이미 잡는 규칙은 지적 대상이 아니다.
8. **규모 게이트** — Must Have급(3파일 이상, API·DB 포함)이면 `code-review` 또는 `simplify`를 서브에이전트 컨텍스트에서 한 번 더(self-grading 편향 회피, `core-tools.md`).
9. **보고** — 실제로 통과한 항목만 `[x]`. 실패했거나 돌리지 못한 항목은 숨기지 않고 **`report.md` "검증하지 못한 것"** 절에 이유와 함께 남긴다 (`{{문서 루트}}/templates/reference-doc.md` "작업 보고서"). 환경이 없어 못 돌린 검증은 실패가 아니라 이 절에 남기는 것이 정상 경로다.

## 금지

- `{{테스트 명령}}` 실행 없이 "통과했을 것"이라고 보고
- 스펙 문구만 보고 구현 상태·완료 여부를 단정
- 실패·미검증 항목을 숨기고 "완료"만 보고
- 계약 변경인데 diff 확인 없이 "계약 그대로"라고 단정
- 사전 모드를 건너뛰고 구현 시작 (명령이 `(없음)`인 저장소는 예외)

## It's working if

- 완료 보고에 "실행한 명령 → 결과" 줄이 있고, 없는 항목은 "검증하지 못한 것"에 이유와 함께 있다
- 구현 도중 "테스트 환경이 안 돌아간다"는 말이 처음 나오는 시점이 사전 모드다
