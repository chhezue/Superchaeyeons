# 매번 읽히는 규칙 줄이기

> 상태: Implemented (2026-10-29) — Nice to Have 남음
> MVP: In scope
> 관련 BR: N/A

이 스펙은 세션마다 통째로 읽히는 규칙 글(약 25KB)을 약 20KB로 줄이는 방법과 순서를 정한다. 읽고 나면 어떤 글을 어디로 옮기거나 지우는지, 무엇은 일부러 남기는지, 줄인 자리가 다시 차지 않게 무엇을 바꾸는지 알 수 있다.

## 목표

규칙을 지키는 힘을 잃지 않으면서 매번 읽히는 글을 약 5KB 줄이고, 새 규칙이 습관처럼 매번 읽히는 글에 쌓이지 않게 한다.

## 이 스펙의 용어

| 용어 | 뜻 |
|---|---|
| 매번 읽히는 글 | 세션마다 처음부터 읽히고 대화가 압축된 뒤에도 다시 읽히는 글. `paths:`가 없는 `.claude/rules/*.md`(`local-*` 제외) · `CLAUDE.md` · `CLAUDE.md`가 `@`로 부르는 파일. `scripts/check-portability.sh`가 바이트로 잰다 |
| 예산 | 매번 읽히는 글의 바이트 상한. 지금 25,000B. 공식 기준이 아니라 이 저장소가 정한 값이다 |
| 차단 메시지 | `deny-*` 훅이 도구 호출을 막을 때 Claude에게 돌려주는 글(stderr) |
| 설명 줄 | 스킬·에이전트 머리말의 `description`. 세션마다 목록으로 읽힌다 |

## 배경

### 지금 상태 (2026-10-28 실측)

| 파일 | 바이트 |
|---|---|
| `.claude/rules/core-workflow.md` | 6,359 |
| `.claude/rules/core-guardrails.md` | 4,850 |
| `.claude/rules/harness-map.md` | 4,841 |
| `.claude/rules/core-gates.md` | 4,078 |
| `AGENTS.md` | 2,788 |
| `.claude/rules/core-reporting.md` | 1,617 |
| `CLAUDE.md` | 462 |
| **합계** | **24,995 / 25,000** |

- 남은 자리가 5B라 새 규칙 한 줄(R-012, 59B)을 넣으려고 예시 하나를 빼야 했다
- 2026-10-27에 24,460B로 줄였는데 하루 만에 약 500B가 다시 늘었다. 줄이기만 하면 며칠 뒤 같은 자리로 돌아온다
- 예산이 세지 않는 글이 따로 있다. 스킬 9개·에이전트 3개의 머리말 합계 4,122B 중 설명 줄은 세션마다 읽힌다
- 서브에이전트는 따로 지정하지 않으면 매번 읽히는 글을 통째로 받는다. 이 저장소 어디에도 `omitClaudeMd` 설정이 없다

### 조사로 확인한 것

공식 문서(code.claude.com `memory` · `context-window` · `skills` · `hooks` · `sub-agents` · `best-practices`, 확인일 2026-10-28, 설치본 Claude Code 2.1.304)와 공개 하네스 6곳(obra/superpowers `2ce8aa15` · affaan-m/everything-claude-code `25278e7d` · wshobson/agents `0874a27b` · SuperClaude-Org/SuperClaude_Framework `fe68862c` · davila7/claude-code-templates `f57964eb` · anthropics/claude-plugins-official `f8c5e7a1`)을 `researcher`로 조사했다.

| 확인한 것 | 이 스펙에 주는 뜻 |
|---|---|
| `@import`는 불러온 파일이 함께 읽혀 글을 줄이지 못한다 | 쓰지 않는다 |
| `paths:` 규칙은 맞는 파일을 읽을 때만 실리고, 대화가 압축되면 사라진다. 문서가 "계속 필요한 규칙은 `paths:`를 빼라"고 적었다 | 멈춤 규칙은 `paths:`로 옮기지 않는다 |
| 스킬 본문은 모델이 불러야 실린다. 이 저장소 시제품에서 스킬 `paths:`도 자동으로 싣지 않았다([플러그인 배달 스펙](harness-plugin-delivery.md) "실험으로 확인한 것") | 구현 도중 지켜야 할 규칙은 스킬로만 두지 않는다 |
| 훅으로 넣은 글(`additionalContext`)은 바이트가 그대로 읽힌다 | 훅 주입은 줄이기가 아니다. 플러그인 배달의 수단일 뿐이다 |
| 공식 문서는 "반드시 지켜야 할 것은 규칙 글이 아니라 훅으로"를 권한다. 차단 메시지는 막히는 순간 Claude에게 전달된다 | 훅이 이미 막는 일의 설명은 차단 메시지로 옮긴다 |
| 공식 문서는 "코드에서 알 수 있는 것은 쓰지 말라"고 한다 | `README.md`·`ls`로 알 수 있는 표는 지운다 |
| `disable-model-invocation: true`인 스킬은 설명 줄이 목록에 실리지 않는다 | 사용자만 부르는 스킬은 설명 줄을 뺄 수 있다 |
| 공개 하네스 중 핵심 멈춤 규칙을 매번 읽히는 글에서 빼는 곳은 없다. superpowers는 3.2KB를 세션마다 다시 넣고, wshobson은 7KB, everything-claude-code는 약 19KB를 둔다. Anthropic 공식 플러그인은 편집한 파일·실행한 명령에 맞을 때만 훅이 경고를 넣는다 | 목표를 "크게"가 아니라 약 20KB로 잡는다 |
| 사용자 표현의 키워드를 보고 규칙을 넣는 훅을 뒤집을 근거는 찾지 못했다 | 계속 기각한다([회고 루프 스펙](harness-retro-loop.md) Out of Scope) |

## 요구사항

### Must Have

**1단계 — 서브에이전트 실험 (규칙 글을 바꾸기 전)**

- [x] 시험용 폴더에서 `.claude/rules/`에 표시 문장을 넣은 규칙 파일과 `omitClaudeMd: true` 에이전트를 만들고, 에이전트가 그 문장을 받는지 `claude -p`로 확인한다. `CLAUDE.md`만 빠지는지, `paths:` 없는 규칙까지 빠지는지를 가른다. **결과(2026-10-28, 2.1.304):** 설정이 없는 에이전트는 `CLAUDE.md`와 규칙의 표시 문장을 둘 다 받았고, `omitClaudeMd: true` 에이전트는 둘 다 받지 않았다. 공식 문서는 "CLAUDE.md 파일"만 적었지만 `paths:` 없는 규칙도 함께 빠진다
- [x] 규칙까지 빠지면 `researcher`·`doc-reviewer`·`test-writer`에 `omitClaudeMd: true`를 넣는다. 세 에이전트 본문에 "호출자가 넘긴 것만 쓴다"가 이미 있는지 확인하고, 없으면 꼭 필요한 멈춤 규칙(위험한 명령 금지는 훅이 막는다)만 에이전트 본문에 한두 줄 둔다
- [x] 세 에이전트 모두 `{{문서 루트}}`·`{{용어집}}` 같은 슬롯을 쓰는데 그 값은 매번 읽히는 `harness-map.md`에 있다. 그래서 본문에 "슬롯 값이 필요하면 `harness-map.md`를 읽는다" 한 줄을 넣었다. 실제 `researcher` 호출로 처음 맥락에 규칙이 없고, 슬롯 값(`docs/`)은 그 파일을 읽어 찾는 것을 확인했다. `harness-map.md`를 읽으면 `.claude/rules/README.md`(`paths:` 규칙, 약 14KB)도 함께 실린다 — 슬롯이 필요할 때만 드는 비용이다

**2단계 — 훅이 막는 일의 설명을 차단 메시지로 (약 -1.4KB)**

- [x] `core-gates.md` 3절에서 훅이 막는 행(작업 범위 밖 수정 · 하네스 자기 수정 · 테스트 없이 완료 선언)의 설명과 "훅 승인 통로" 문단(515B)을 해당 `deny-*` 훅의 차단 메시지로 옮긴다. 메시지에는 "구두 승인으로 풀리지 않는다 · 사용자가 바꿀 상수 · 한 줄로 보고하고 멈춘다"를 넣는다
- [x] 매번 읽히는 글에는 훅이 못 보는 우회만 한 줄로 남긴다: Bash·변수·`eval`·별도 스크립트로 훅 대상 파일을 고치거나 막힌 일을 하지 않는다
- [x] `core-gates.md` 2절 "훅이 막음 → 3절" 행이 가리키는 곳을 새 위치에 맞춘다
- [x] `core-guardrails.md` "훅이 막는 것과 못 보는 것"(325B)에서 `.claude/rules/README.md` "훅 공통 규약"과 겹치는 부분을 지우고, 규칙으로만 막는 한 줄(API 키를 파일·로그에 쓰지 않기)만 §1 끝에 남긴다

**3단계 — 코드·README로 알 수 있는 정보 정리 (약 -1.7KB)**

- [x] `AGENTS.md` "무엇이 들어 있나" 표(1,032B)를 `README.md` 디렉터리 안내를 가리키는 한 줄로 바꾼다. 표에만 있고 `README.md`에 없는 사실(예: "새 프로젝트로 복사 여부" 열)은 `README.md`로 옮긴 뒤 지운다
- [x] `harness-map.md` "스택 팩" 표(233B)와 플래그 표 아래 설명 문단을 지운다. lang 팩 목록은 `ls .claude/rules/local-*`로 알 수 있다
- [x] `harness-map.md` "축" 표(511B)를 한 줄 요약으로 바꾼다. `init-harness`가 이 표를 채우므로 스킬의 2단계 안내와 `examples/baro/harness-map.md` 견본도 같은 턴에 맞춘다
- [x] `harness-map.md` 모양이 바뀌면 `.claude/rules/README.md` "옛 모양 map 정리"에 한 줄을 더해, 이미 붙인 프로젝트가 `init-harness` 재동기화 때 따라오게 한다

**4단계 — 레거시 삭제의 상세 목록만 `verify-work`로 (약 -1.0KB)**

- [x] `core-guardrails.md` §2는 멈춤 규칙 세 줄만 남긴다: 호환용으로 남기지 않는다 · 같은 변경에서 지운다 · 이번 변경이 대체한 것은 요청 범위다. "삭제 대상" 목록과 예외 설명은 `verify-work` 레거시 재점검 단계로 옮긴다
- [x] §2는 구현 도중에 지켜야 하는 규칙이라 통째로 옮기지 않는다. `verify-work`는 끝날 때 불려서 늦기 때문이다

**5단계 — 줄인 자리가 다시 차지 않게**

- [x] `scripts/check-portability.sh` 예산에 스킬·에이전트 설명 줄을 더한다. 상한은 25,000B 그대로다
- [x] `.claude/rules/README.md`에 "새 규칙을 넣을 곳" 기준을 둔다: exit code로 판정되면 훅 → 끝난 뒤 확인해도 되면 `verify-work` 점검표 → 특정 파일을 다룰 때만 필요하면 `paths:` 규칙 → 구현 도중 늘 지켜야 할 때만 매번 읽히는 글. 회고 루프의 분석 지시문(`.claude/skills/improve-harness/references/analyze.md`)의 "고칠 층"도 같은 순서를 따른다

### Nice to Have

- [ ] `core-workflow.md` G2~G4(약 3.5KB)를 게이트별 멈춤 조건만 남기고 스킬로 넘기기. 스킬 본문과 줄 단위 중복을 대조한 뒤 별도 스펙으로 판단한다. "승인 전 구현 금지"와 커밋 승인은 훅이 지키지 못하므로 남긴다
- [ ] 한국어 글의 실제 토큰 수를 `/context`로 재서 "바이트 ÷ 2.5" 추정을 고친다

### Out of Scope (이번 스펙에서 하지 않음)

- 멈춤 규칙(`core-guardrails` §1 문서·구현 정합, `core-gates` 1·2절)을 `paths:`·스킬로 옮기기 — 압축 뒤 사라지거나 불려야만 실린다
- 규칙을 훅 주입이나 출력 스타일로 옮기고 "줄였다"고 보기 — 바이트가 같다. 훅 주입은 [플러그인 배달 스펙](harness-plugin-delivery.md)이 다룬다
- 사용자 표현 키워드로 규칙을 넣는 훅
- 줄인 뒤 실제로 더 잘 지켜지는지 재기 — 비교할 기준이 없다. 회고 루프의 재발 횟수로 간접 확인한다
