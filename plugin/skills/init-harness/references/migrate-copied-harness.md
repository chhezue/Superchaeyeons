# 복사한 하네스를 플러그인으로 이전

기존 프로젝트의 훅·규칙·양식을 옮길 때만 이 절차를 연다. 새 설치는 초기화 스킬의 일반 실측으로 시작한다.

## 무엇을 쓰고 있는지 확인

1. 저장소 루트와 작업 범위를 확인한다. `plugin/scripts/init-harness-probe.sh <저장소> <범위> --migration`을 설치된 플러그인에서 실행한다. 실제 Git 훅 디렉터리, 실행 권한, 링크 대상, 예전 파일 경로를 쓰는 문서·주석·스크립트의 위치가 나온다. 참조는 작업 범위 밖에도 있을 수 있어 저장소 전체를 읽는다. 프로젝트 지침과 거기서 연결한 등록부에서 다른 위치의 규칙·양식도 찾는다. 무시된 파일과 실행 중 조합하는 경로는 실제 등록·설치 스크립트에서도 확인한다. 결과가 길면 임시 파일에 보관하고 정리 대상의 참조를 골라 읽는다.
2. 후보마다 설치 당시 원본이나 확인된 설치 커밋과 **지금 작업 파일**을 대조한다. Git 이력은 `git log --follow -- <경로>`로 찾는다. 동일본·프로젝트 수정본·출처 불명 중 하나와 근거를 적는다. 처음 추적된 커밋만으로 배포 원본이라고 단정하지 않는다. 출처 불명은 보존한다.
3. Git 훅의 호출자는 사람이 직접 하는 커밋까지 포함한다. 실제 설치된 훅이 다른 프로젝트 스크립트를 호출하는지도 확인한다. 에이전트의 편집·커밋 검사로 대체하면 사라지는 검사를 적는다. PR 템플릿 주석의 일반 경로, 이동할 양식 *안에서* 다른 파일을 가리키는 상대 링크도 확인한다.

## 승인안

후보마다 아래 한 행을 채운다. 보존할 기능과 적용 대상이 드러나는 구체적인 변경안을 보여주고 승인을 기다린다.

| 현재 경로 · 출처 근거 | 사용 주체 · 시점 | 보존·이동·대체·삭제 제안 | 함께 바꿀 참조 | 적용 후 검증 |
|---|---|---|---|---|
| 조사에서 확인한 경로와 비교 결과 | 직접 커밋·에이전트·문서 독자 등 | 이동이면 도착 경로, 대체면 동작 차이 | 참조 파일과 줄, 옮긴 문서의 상대 링크 | 실행할 동작과 기대 결과 |

예전 `harness-map.md`의 축·슬롯·플래그, 훅 본문의 프로젝트 상수는 실제 사용값을 공통 설정 키와 대조한다. 설정에서 중복 훅을 걷어낼 때는 해당 등록 항목만 제안한다. `local-*`과 `scripts/dev.conf`는 프로젝트 소유다. 같은 이름의 Git 훅·규칙·스크립트도 경로만으로 지우지 않는다. 사용처·대체 동작이 확인된 동일본만 정리 후보로 올린다.

## 승인 후 검증

- 승인된 파일과 참조만 변경한다. 이전안을 다시 만들고 같은 이동·삭제가 남았는지 본다. 변경 전 목록으로 옛 경로를 다시 검색하고, 새 위치를 기준으로 문서 내부 링크와 프로젝트 지침을 따라가 본다.
- 실제 훅 디렉터리·링크 대상·실행 권한을 대조한다. 실행 시험은 임시 저장소에서 한다. 부분 스테이징한 파일과 별도의 미스테이징 파일을 마련해 성공·실패·포매터가 스테이징한 줄을 다시 쓰는 경우를 이전 전후 같은 조건으로 실행한다.
- 종료 코드, 인덱스에 들어간 내용과 충돌, 작업 파일 바이트, 남은 stash를 비교한다. 새 차이는 승인 범위와 맞는지 확인한다. 이미 있던 충돌과 검증할 수 없던 동작도 보고한다. 사용 중인 작업 디렉터리를 시험용으로 스테이징하거나 stash하지 않는다.
