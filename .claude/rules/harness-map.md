# Harness Map — 이 프로젝트의 슬롯

규칙(`core-*.md`)은 경로·명령을 `{{역할 이름}}`으로 부르고, 이 파일이 실제 값을 잇는다. **새 프로젝트가 채우는 파일은 이것 하나다** (`adopt` 스킬 · 채운 예: `examples/baro/harness-map.md`).

## 규칙

1. 빈 슬롯은 `(없음) — 이유`로 적는다 — "안 정했다"와 "이 프로젝트엔 없다"를 가르기 위해
2. `(없음)`인 슬롯을 규칙이 요구하면 멈추고 사용자에게 묻는다
3. 슬롯·플래그는 `core-*.md`가 실제로 쓸 때만 둔다 — `scripts/check-portability.sh`가 슬롯 정의와 사용을 대조한다
4. 옵션을 끄려고 규칙 절을 지우지 않는다 — ❌면 `[플래그: X]` 절을 무시한다
5. `core-*.md`는 손대지 않는다. 고유 사실은 이 파일(값)과 `.claude/` 안의 `local-*`(규칙·복사한 씨앗)에만

**훅 상수와 짝:** 훅·git 훅은 이 파일을 읽지 못해 값을 본문에 직접 적는다. 아래 값을 바꾸면 짝을 같은 턴에 고친다.

- `{{작업 범위}}` ↔ `deny-out-of-scope-write.sh`의 `SCOPE`
- "하네스 자기 수정" ↔ 같은 훅의 `HARNESS_SELF_EDIT`
- `{{테스트 명령}}` ↔ `deny-unverified-completion.sh`의 `TEST_CMD`
- `{{커밋 메시지 형식}}` ↔ `scripts/git-hooks/commit-msg` 정규식
- `{{포맷 명령}}` ↔ `scripts/git-hooks/pre-commit`의 `FORMAT_CMD`와 씨앗 포맷 훅

## 축

값은 붙이는 시점에 실측해 적는다. 규칙은 축을 직접 부르지 않는다 — 슬롯·플래그 값을 고르는 근거다.

| 축 | 이 프로젝트 |
|----|-------------|
| **lang** | 없음 — 애플리케이션 코드가 없는 문서·스크립트 저장소(md·sh). 훅·검사기는 `bash`·`python3` 전제 |
| **shape** | 단일 저장소 · 문서 루트 `docs/` · `.github/` 쓰기 가능 · 작업 범위 = 저장소 전체 |
| **deploy** | 없음 — 배포·외부 클라이언트 없음 |
| **stage** | 초기 · 운영 데이터 없음 · 계약은 core 부품 계약 하나(`scripts/check-portability.sh`) |

| 슬롯 | 이 프로젝트 |
|------|-------------|
| `{{문서 루트}}` | `docs/` |
| `{{작업 범위}}` | `.` — 저장소 전체라 범위 검사 생략 |
| `{{Git 컨벤션 SSOT}}` | `.github/CONTRIBUTING.md` — `(없음)`이면 `core-workflow` G2·G4가 SSOT |

| `{{우선순위 SSOT}}` | (없음) — 이슈 우선순위 라벨 체계가 없다. 작업 순서는 스펙의 `단계(Phase)` 표 |
| `{{아키텍처 개요}}` | `docs/harness/README.md` |
| `{{스키마 SSOT}}` | (없음) — DB 없음 |
| `{{API 응답 규격}}` | (없음) — API 없음 |

| `{{제품 범위}}` | `AGENTS.md` |
| `{{클라이언트 전제}}` | (없음) — 클라이언트 없음 |
| `{{용어집}}` | (없음) — 하네스 용어(축·슬롯·플래그·트랙·규모·게이트)는 이 파일과 `core-workflow.md`가 정의 |
| `{{결정 기록}}` | `docs/decisions/` |
| `{{감사 로그}}` | `docs/audits/` |
| `{{배포 SSOT}}` | (없음) — 배포 없음 |

## 명령·형식 슬롯

기존 저장소에 붙일 때는 기본값을 물려받지 않고 `adopt`이 이력에서 실측한다.

| 슬롯 | 이 프로젝트 |
|------|-------------|
| `{{테스트 명령}}` | `scripts/verify.sh` — 검사기 3개 래퍼. "통과" 판정은 이 명령으로 |
| `{{빌드 명령}}` | (없음) — 빌드 없음 |
| `{{포맷 명령}}` | (없음) — 포맷 도구 없음 |
| `{{의존성 조회}}` | (없음) — 의존성 없음 |
| `{{브랜치명 형식}}` | `{type}/{issue-number}-{description}` |
| `{{커밋 메시지 형식}}` | `{Type}: {한글}` |

## 능력 플래그

규칙의 `[플래그: X]` 절은 ☑면 적용, ❌면 무시, ⬜(미결정)면 멈추고 묻는다. 스택 플래그의 본문은 lang 팩 절에 있다.

| 플래그 | 값 | 부르는 곳 → 본문 | 켜거나 끌 때 할 일 |
|--------|-----|------------------|-----------------|
| **DB 마이그레이션 금지** | ❌ | `core-guardrails` §2 → lang 팩 "DB 스키마 정책" | ☑면 씨앗 `local-deny-db-migration.sh` 복사·등록. **운영 DB가 있으면 반드시 ❌** |
| **에러 코드 카탈로그 동시갱신** | ❌ | `core-guardrails` §1.7 → lang 팩 "같은 턴 즉시 갱신" | — |
| **권한 게이트·활동 기록 동시갱신** | ❌ | `core-guardrails` §1.7 → lang 팩 "같은 턴 즉시 갱신" | — |
| **API 계약 보호** | ❌ | `core-workflow` G3 · `preflight` 4단계 → lang 팩 "API 계약 변경" | ☑면 씨앗 `local-warn-breaking-change.sh` 복사·등록 |
| **생성 문서 검증** | ❌ | `core-guardrails` §1.6 → lang 팩 "생성 문서 검증" | — |
| **스택 함정 메모** | ❌ | `core-workflow` G1 → lang 팩 "스택 함정 메모" | — |
| **스택 리뷰어** | ❌ | `core-workflow` G3 · `preflight` 7단계 → 리뷰어 에이전트 | — |
| **하네스 자기 수정** | ☑ | `core-gates` §3 | ❌면 `HARNESS_SELF_EDIT="0"`. **붙여 쓰는 프로젝트는 ❌가 기본** |

이 저장소는 DB·API·애플리케이션 코드가 없어 스택 플래그가 전부 ❌이고, 하네스 자체를 고치는 곳이라 자기 수정만 ☑이다.

## 스택 팩 (= lang 팩)

이 저장소 `.claude/`에 실제로 있는 lang 팩 파일이다. `adopt`이 씨앗(`examples/seeds/{스택}/`)을 `local-*` 이름 그대로 복사하거나 `_template/`을 채운다. 클라이언트 전제·배포 토폴로지처럼 스택이 아닌 고유 사실은 `local-*.md`로 쓴다.

|----|------------------|-----------|
| (없음) — lang 축이 없음 | — | — |
