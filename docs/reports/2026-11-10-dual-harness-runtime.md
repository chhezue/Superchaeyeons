# 공동 지원 연결 — 검증 보고서

Claude Code 플러그인을 보존하며 Codex의 승인 사전 검사·규칙·완료 확인·회고·초기화를 연결했다. 자동 검사와 임시 설치에 이어, 승인된 연습용 프로젝트에서 CLI 훅 신뢰·실제 도구 차단·완료 확인·역할 호출을 검증했다. 이 문서는 커밋 전 검수 결과이며 실제 사용 프로젝트의 신뢰는 프로젝트별로 검토한다.

## 무엇을 했나

| 영역 | 변경 |
|---|---|
| 차단 | Codex 명령·패치 전체를 기존 위험 명령·범위 판정기에 연결. 추가·수정·삭제·이동 양쪽과 자기 수정·증거 상태 보호 |
| 승인 | 기존 ask-approval 판정을 allow/confirm/deny로 바꾸는 사전 검사. Codex 런타임에 미지원 ask를 등록하지 않음 |
| 규칙·포맷 | 공통 규칙·설정·경로 규칙·포맷을 재사용. 세션·역할·세대별 중복 방지 |
| 완료 확인 | 공통 완료 문구·Bash 편집·실패 요약 정책을 한 원본으로 추출. Codex는 테스트 시작 ID·편집 세대·최종 응답으로 증거 기록 |
| 초기화 | Claude / Codex / 둘 다 선택. 공통 설정 한 벌, 기존 권한·주석·값 보존. 충돌·링크는 적용 거절 |
| 역할 | 3개 공통 역할의 TOML 생성. 모델 상속, test-writer shell 비활성 선언. 생성 파일은 초기화로 재동기화 |
| 회고·다듬기 | 도구별 대기열·세션·장부·기준판 분리. Codex는 현재 프로젝트 사용자 메시지와 확인한 feedback을 자체 형식으로 기록·해석 |
| 분석 실행기 | 기존 Claude 실행기·모델·1달러 상한·첫 수동 분석 후 7일 자동 조건 유지. Codex만 설치한 환경은 분석 실행기 별도 필요 |

기존 `.claude/settings.json`의 사용자 변경과 `.agents/`는 보존했다. 이 저장소 `.claude/harness.conf`의 테스트 경로는 사라진 `scripts/dev.sh`에서 실제 `plugin/scripts/dev.sh`로 바로잡았다. 이전 연결 검수에서는 이슈·브랜치 생성·커밋·push·PR·머지·전역 신뢰 변경을 하지 않았다. 이번에는 사용자가 검수 후 커밋과 PR 없는 main 반영을 승인했다. 연습용 임시 환경의 훅만 공식 검토 화면에서 신뢰했다. 사용자 전역 설정과 실제 프로젝트의 신뢰는 변경하지 않았다. 이동·삭제한 프로젝트 파일은 없다.

현재 프로젝트의 사용자 메시지 원문을 `.codex/corrections/sessions/`에 로컬 보관하며 버전 관리에서 제외한다. 수집 시 정정 여부를 추정하지 않는다. 분석 실행 때 추출·길이 제한한 메시지를 기존 Claude 분석기로 전달한다.

| 검증 | 결과 |
|---|---|
| Codex 설치본 | codex-cli 0.167.0-alpha.3.2 |
| 임시 설치 | 별도 CODEX_HOME에서 marketplace 등록·설치 성공. 사용자 전역 설정 미변경 |
| 설치 캐시 대조 | 소스 파일 54개와 설치된 파일이 전부 일치 |
| 실제 skills/list | superchaeyeons의 8개 스킬 발견, 오류 없음 |
| 실제 hooks/list | 12개 핸들러 발견, 오류 없음. 최초 untrusted 확인 뒤 공식 화면에서 12개 신뢰. 스크립트 변경 후 재검토 요구·재신뢰 확인 |
| 실제 execpolicy check | 생성 규칙에서 git commit·gh pr create는 prompt, git status는 일치 규칙 없음 |
| 생성 TOML | 표준 파서와 기존 값 보존·타입·충돌·멱등성 테스트 |
| Claude 회귀 | 공유 완료 정책 변경 뒤 기존 Stop 41개 통과 |
| 전체 검사 | 임시 Claude Code 2.1.322로 `plugin/scripts/dev.sh test` 실행, 9단계 전부 통과 |

최초 전체 검수는 훅 데이터 637개·보조 2개, 등록 20개, 세션 23개, 설정 20개, 회고 18개가 통과했다. 이후 실제 실행에서 발견한 경계의 회귀를 추가해 세션 검사는 30개다. 최종 전체 검사는 추가 케이스를 포함해 다시 실행한다. 문서 검사의 오류만 실패로 판정하며 약어 등 경고는 별도 유지한다. Gemini 문서 다듬기는 키가 없어 건너뛰었다.

실제 유료 회고 분석과 Gemini 네트워크 호출은 실행하지 않았다. 회고는 가짜 실행기에서 입력·종료 코드·모델·비용 상한 인자를 확인했다.

## 실제 실행에서 찾은 문제

기존 입력 기반 검사에는 Bash의 응답이 exit_code 객체로 들어갔다. 실제 설치본은 stdout 문자열만 보냈다. 성공한 테스트가 증거로 남지 않았고, apply_patch의 Exit code·Wall time·Output 응답 머리도 해석하지 못했다.

독립 테스트 6개가 수정 전 실패하는 것을 확인하고 다음과 같이 고쳤다. 수정 뒤 29개가 통과했으며, 구현을 되돌리면 같은 6개가 다시 실패했다.

- 단독 전체 테스트를 별도 셸로 감싸 실제 종료 코드를 받는다. 표식은 호출별 nonce와 실제 물리 작업 폴더를 포함한다.
- 같은 호출 ID·명령·편집 세대와 루트 폴더가 맞을 때만 성공으로 인정한다. 단순 OK, 다른 호출 표식, Bash가 출력한 가짜 응답 머리는 거절한다.
- apply_patch만 실제 관찰한 응답 머리에서 종료 코드를 읽는다. 성공한 패치 뒤 공통 경로 규칙·포맷이 실행된다.

다른 폴더의 같은 문자열 테스트가 루트의 전체 테스트로 인정되는 경계도 별도 실패 테스트로 재현했다. 수정 뒤 독립 세션 검사 30개가 통과했다. 이번 native 응답 수정에는 새 파일·의존성·전역 설정을 추가하지 않았다.

## 신뢰 후 실제 실행 결과

모든 명령은 원격 없는 연습용 프로젝트에서 Codex가 실제 도구로 호출했다. 설치 캐시 54개 파일이 최종 소스와 일치함을 대조했다. 실제 검수일은 2026-11-10이며 커밋 메타데이터 날짜와 구분한다.

| 시나리오 | 실제 결과 |
|---|---|
| 위험 명령 | force push의 dry-run 호출이 PreToolUse에서 차단됨. 명령 실행·원격 변경 없음 |
| 보호 파일 패치 | .codex/config.toml 주석 추가 시도가 차단됐고 파일 내용 유지 |
| 일반 패치 후처리 | 코드 변경 뒤 경로 규칙이 주입되고 설정한 포맷 명령이 실행됨 |
| 테스트 없는 완료 | 코드 편집 뒤 구현 완료 응답을 Stop이 blocked로 되돌림 |
| 전체 테스트 성공 뒤 완료 | 같은 대화에서 단독 전체 테스트 exit 0 뒤 tested=true·pending 비움, 다음 Stop completed |
| 작업 폴더 보존 | exec_command의 workdir을 다른 폴더로 지정했을 때 그 폴더에서 실행되고 의도적 실패 exit 1 유지 |
| 사용자 메시지 | 자체 sessions JSONL에 기록, Claude 회고 상태 생성 없음 |
| test-writer | 실제 역할 호출. exec_command·write_stdin 없음 보고와 부모 gpt-6.1-sol·medium 상속 이벤트 확인 |
| 대화 보존 조건 | ephemeral 대화에서는 역할 호출에 필요한 이력이 없어 실패. 이력을 저장하는 연습 대화에서 역할 호출 성공 |

대표 완료 차단·복구 대화 ID는 01a1c591-f839-7e41-a980-19cb7e9845e4다. 도구 호출·훅 상태 이벤트로 결과를 대조했으며 모델의 성공 보고만 근거로 삼지 않았다. 임시 실행 원본은 개인 로그인·대화 기록과 함께 삭제하고 이 보고서에 결과를 남긴다.

| 항목 | 이유·필요한 확인 |
|---|---|
| 실제 사용자 프로젝트·앱 화면 | 연습용 CLI 환경에서 실제 실행을 검증했다. 사용자의 기존 프로젝트·앱 설정은 변경하지 않음 |
| 역할의 다른 도구 경로 | test-writer의 셸 도구 부재와 부모 모델 상속은 실제 확인. 모든 도구 경로에 대한 완전한 격리를 보장하는 검수는 아님 |
| 로그인한 Claude 세션의 승인 창 | 임시 CLI의 정적 검사와 기존 회귀만 수행. 로그인·사용자 설정 변경은 범위 밖 |
| 실제 분석 비용·모델 결과 | 별도 유료 분석을 호출하지 않음. 코드의 상한 전달과 성공·실패 처리를 검증 |
| Gemini 다듬기 | 키 없음. 로컬 기준판과 기존 네트워크 대역 테스트만 수행 |
| 플랫폼 자체 훅 오류·시간 초과 | 정상 차단과 프로세스 실패의 exit 2 변환은 검수했으나 플랫폼 자체 실패에서의 강제 차단은 보장하지 않음 |
| 클라우드의 로컬 훅 | 지원 대상 밖. 로컬 앱·CLI 지원과 구분 |

## 실행 비용

저장소 검사기의 상시 로드 예산은 5,628B로 시작 기준 5,649B보다 21B 줄었다. 공통 규칙 주입은 8,164자로 기존 8,018자보다 146자 늘었고 9,000자 상한 안이다. Codex 연결 안내는 별도 세션 훅으로 주입한다. 역할 본문은 역할 호출 때 읽는다. 도구별 연결은 로컬 프로세스·상태 입출력을 추가한다. 일반 규칙·검증 훅은 모델을 호출하지 않으며, 회고 분석만 기존 최초 수동 실행 조건과 비용 상한을 따른다.

## 임시 검수 환경

공식 배포 파일의 해시와 서명을 확인한 Claude Code 2.1.322를 임시 폴더에서만 실행했다. 전역 설치·로그인은 하지 않았다. 검사 결과는 이 보고서에 남기며, 임시 CLI와 Codex 설치 실험 폴더는 검수 마무리 때 삭제한다.

## 남은 것

- 실제 사용 프로젝트에서는 설치된 출처와 훅을 검토한 뒤 신뢰한다. 연습용 CLI 검수를 앱 화면 검수와 혼동하지 않는다.
- 생성 역할은 플러그인 업데이트 뒤 init-harness로 재동기화한다.
- 사용자가 승인한 `Feat: Claude와 Codex 하네스 공동 지원` 커밋으로 main에 직접 반영한다. 새 커밋의 작성일·커밋일은 2026-11-08 한국 시간이다. 기존 원격 이력은 덮어쓰지 않는다.
- 원격 반영 뒤 별도 임시 환경에서 GitHub 경로로 설치하고 커밋·캐시·스킬·훅을 대조한다. 공식 디렉터리 등록은 범위 밖이다.
