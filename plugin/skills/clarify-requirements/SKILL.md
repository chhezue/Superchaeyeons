# 구현 결과를 바꾸는 요구사항 확인

먼저 저장소·승인된 스펙에서 답을 찾는다. 이름·파일 위치처럼 기존 관례로 정할 수 있고 쉽게 되돌릴 수 있는 선택은 그 관례를 따른다. 요청이 짧아도 결과가 하나로 정해지면 진행한다.

1. 답에 따라 사용자 동작, 외부 계약, 비용, 권한 또는 승인 범위가 달라지는 결정을 추린다. 통제 영역은 `core-approval-triggers.md`를 따른다.
2. 결정 간 의존성이 있으면 앞선 결정부터 묻는다. 질문에는 확인한 사실, 선택지별 결과와 권장 이유를 담는다. 사용자가 함께 묻기를 원하면 독립적인 질문을 묶는다.
3. 확정된 답을 스펙 또는 감사 항목에 반영한다. 이미 승인된 결정은 재개할 때 그대로 사용하고, 충돌이나 범위 변경이 발생한 항목만 다시 확인한다. 스펙 승인이나 실제 커밋처럼 별도 승인이 필요한 작업은 해당 절차를 따른다.
