# 안 하기로 한 것 (Out of Scope)

이 하네스가 **검토한 뒤 채택하지 않은 장치와 결정**을 이유와 함께 모아 둔 목록이다. 같은 논쟁이 반복되는 것을 막는 장치다 — 새 도구를 제안하기 전에 여기서 이미 기각된 것인지 먼저 본다. 상황이 바뀌어 다시 검토하면 이 표의 행을 고치고 근거를 갱신한다. 행마다 판정 기준은 둘 중 하나다 — 하네스 장치는 부품성 원칙(장치 하나는 bash 하나 + 데이터 파일 하나 · 새 개념은 기존 개념을 대체해야 함 · 스택에 묶이는 것은 팩으로), 서드파티 도구는 `core-tools.md` 채택 기준(문서가 단순해지고 · 반복을 없애고 · 유지보수성이 오르고 · 토큰이 줄어야 함).

## 언제 이 문서를 보는가

- 서드파티 플러그인·새 훅·새 스킬·새 디렉터리 구조를 제안하려 할 때
- "왜 X를 안 쓰나"라는 질문을 받았을 때

## 목록

| 무엇 | 왜 안 하나 | 다시 볼 조건 | 결정일 |

| **서드파티 워크플로 플러그인** (Superpowers · OMC 류) | brainstorming·계획·실행은 Plan Mode와 `ask`·`specify`가, 코드 리뷰는 `code-review`/`simplify`가, 병렬 탐색은 `Agent` 툴이 이미 대체한다. 설치본은 수정할 수 없고 영어이며, 전면 TDD 같은 원칙이 이 하네스의 "유의미한 테스트만"과 충돌한다. 채택 기준(문서가 더 단순해지고 · 반복을 없애고 · 토큰이 줄어야 함)을 하나도 만족하지 못했다 | 특정 gap이 실제로 반복 비용을 낸다고 실측될 때 | 2026-07-23, 2026-09-05 재확인 |
| **`packs/` 디렉터리 + `pack.md` 계약** | 축 4개는 `adopt`이 무엇을 물을지 정하는 질문 목록으로 충분하고, 플래그를 어느 파일이 구현하는지는 `harness-map.md` 플래그 표가 이미 담는다. 계약 파일은 같은 정보를 다른 형식으로 한 번 더 적는 일이다. 생성물 품질은 `adopt` 산출물 체크리스트가 맡는다 | 체크리스트로 생성물 품질이 흔들리는 사례가 실제로 나올 때 | 2026-09-05 |
