# Core — 가드레일 (⛔ STOP)

구현·기본값 변경·커밋 **전에 멈춰야 하는 것**만 모았다. 여기 걸리면 다른 규칙·워크플로보다 먼저 중단하고 사용자에게 묻는다. 작업 순서는 `core-workflow.md`, 그 밖의 멈추는 신호는 `core-gates.md`가 갖는다.

**플래그 판정:** `[플래그: X]`가 붙은 절은 `harness-map.md` 능력 플래그 표에서 X가 ❌면 무시하고, ⬜(미결정)면 멈추고 묻는다. 절을 지우지 않는다 — 지우면 부품이 갈라져 이후 개선을 함께 받을 수 없다. 스택에 묶인 STOP 절(에러 코드·권한·활동 기록 동시갱신 · 마이그레이션 · API 계약 · 생성 문서)의 본문은 lang 팩 규칙에 있다.

## §1. 문서·구현 정합

1. **문서 vs 구현** — `{{스펙 저장소}}`(Approved)·`{{결정 기록}}`(확정)·`{{제품 범위}}`·`{{아키텍처 개요}}`·`{{배포 SSOT}}`와 다른 TTL·API 계약·enum·한도·env 이름·패키지 경로를 조용히 맞추지 않는다
2. **문서 vs 문서** — PRD vs 스펙, 스펙 vs 와이어프레임, decisions vs architecture, 스펙 vs `.env.example`처럼 두 문서가 다른 값·용어·경로를 말하면 한쪽을 고르지 말고 충돌을 목록으로 보여 확인받는다
3. **임의 개선 금지** — "더 나은 기본값"·"업계 일반값"·"코드가 간단해짐"만으로 문서와 다른 수치·구조를 쓰지 않는다. 바꾸려면 문서 amend 또는 사용자 명시 승인
4. **불확실하면 질문** — 가정을 숨기지 않는다. 질문 없이 진행한 선택은 잘못된 작업이다
5. **"미구현"이라고 단정하기 전에 코드부터** — 스펙 체크박스·"미구현"·"`#n` 선행 필요" 같은 서술은 merge 뒤 동기화가 빠지면 틀린다. 진입점·이벤트 발행부·테스트를 직접 grep/Read하고, 이슈 상태는 `gh issue view`로 본다. 스펙 문구 하나만 근거로 구현 여부를 답하지 않는다
6. **[플래그: 생성 문서 검증]** "생성 문서에 이미 있다"고 답하기 전에 생성물이나 `{{API 문서}}`를 실제로 연다 — 소스에 설명 표기가 있어도 스키마가 통째로 빠질 수 있다 (lang 팩 "생성 문서 검증" 절)
7. **계약에 닿는 변경은 같은 턴에 끝낸다** — 실패 케이스·에러 코드·권한 게이트·활동 시각 기록처럼 코드와 계약·문서·생성물이 함께 바뀌어야 하면 enum·스펙 에러 표·응답 스키마·주석까지 같은 PR·같은 턴에 고친다. "다음 커밋에" 금지 (스택별 체크 표: lang 팩 **[플래그: 에러 코드 카탈로그 동시갱신]**·**[플래그: 권한 게이트·활동 기록 동시갱신]**)
8. **`[미정]`은 표기만** — 기획·스펙의 미확정 항목은 그 문서에 `[미정]`만 남기고 임의로 확정해 구현·커밋하지 않는다. 중앙 트래커 이슈를 만들거나 되살리지 않는다. 확정되면 문서를 amend하고 별도 작업으로 구현한다. 우선순위 라벨·릴리즈 사실은 `local-priority.md`·`local-release.md`(있을 때만)가 갖고, 라벨은 사용자 확인 없이 붙이거나 바꾸지 않는다

## §2. 레거시 즉시 삭제 — 호환 레이어 금지

현행 Approved 스펙·BR·decisions·구현 계약과 다른 코드·경로·문서를 "호환용"으로 남기지 않는다. 운영 보존 데이터가 없으면 듀얼 패스·구 클라/DB 호환·orphan 유지는 금지다. 운영 데이터가 있는 프로젝트("DB 마이그레이션 금지" ❌)는 구 스키마 매핑과 구 클라/DB 호환을 그 프로젝트의 마이그레이션 정책으로 판단하고, 나머지는 그대로 적용한다.

- **삭제 대상:** 폐기 API/path · 폐기 enum/에러 코드/필드 · 구 상수·검증 · 대체된 저장 계층 메서드·벌크 쿼리 · 호환 if · deprecated 표시만 한 코드 · stale 스키마 설명·메시지 · "나중에 지울" TODO · 스펙·생성 문서에 **현행으로 적힌** 구 수치·구 API명
- **시점:** 정책 amend·경로 교체와 같은 커밋·PR·턴. "다음 커밋에 정리"·"일단 새 경로만 추가" 금지
- **교체 = 구경로 삭제:** 이번 변경이 대체한 구 메서드·상수·테스트 assert·문서의 '현행' 문구는 요청 범위다. "요청 밖 dead code라서 언급만" 하고 넘기지 않는다
- **예외:** 이번 정책과 무관한 기존 dead code는 언급만 한다. 스펙 Changelog의 "당시 값은 이랬다"는 이력이라 둔다

## §3. 보안·아키텍처 변경 — 현재동작 요약 갱신

인증·세션·토큰 저장 방식, 비밀번호·시크릿 처리, 결제 흐름, 개인정보 저장·암호화·대량 접근처럼 "바뀐 걸 사용자가 한참 뒤에야 알면 곤란한" 로직을 바꾸면, 같은 턴에 `{{현재동작 요약}}`의 해당 절을 다른 문서 없이 읽히는 쉬운 말로 고친다(없던 주제면 절을 추가). 스펙에만 적고 넘어가거나 "사소한 변경"이라며 생략하지 않는다.

## 훅이 막는 것과 못 보는 것

파괴·우회·시크릿 명령(force push · 재귀 삭제 · hard reset · `--no-verify` · `.env` 커밋 · SQL `DROP` 등)은 `deny-dangerous-bash.sh`가 실행 전에 막는다 — 목록 SSOT는 훅의 `PATTERNS`. 훅이 못 보는 것은 이 규칙으로만 금지한다: API 키를 파일·로그에 쓰기 · 변수·`eval`·별도 스크립트로 감싼 간접 실행.
