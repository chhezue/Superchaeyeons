# Gemini 글 다듬기

> 상태: Approved (2026-10-28 사용자 승인)
> MVP: In scope
> 관련 BR: N/A

사람에게 남는 글(문서, 커밋 메시지, PR, 이슈)을 Claude가 쓴 뒤 Gemini가 한 번 더 다듬고, Claude가 사실이 바뀌지 않았는지 검수해 확정하는 흐름의 스펙이다. 무엇을 언제 보내는지, 무엇은 절대 바꾸지 않는지, 실패하면 어떻게 되는지를 정한다.

## 목표

남는 글을 Claude 혼자 쓸 때보다 읽기 쉽게 만들되, 경로나 숫자 같은 사실은 한 글자도 바뀌지 않게 한다.

## 이 스펙의 용어

| 용어 | 뜻 |
|---|---|
| 다듬기 | Gemini가 문장만 고쳐 쓰는 것. 내용을 더하거나 빼지 않는다 |
| 사람용 문서 | 다듬기 대상인 마크다운 파일. 범위는 Must Have의 "대상" 묶음 |
| 남는 글 | 저장소나 GitHub에 기록으로 남는 글. 문서, 커밋 메시지, PR 제목과 본문, 이슈, PR이나 이슈 댓글 |
| 원문 | Claude가 쓴 글. Gemini가 다듬기 전의 글 |
| 작성이 끝나는 시점 | 그 문서를 사람이 처음 읽게 되는 하네스 흐름의 지점. Must Have의 "문서 다듬기" 묶음이 정한다 |
| 기준판 | 바뀐 문단을 찾을 때 비교하는 판. 마지막으로 다듬기를 확정한 판이고, 없으면 마지막 커밋의 판이다 |
| 상태 폴더 | 기준판과 다듬기 기록을 두는 `.claude/polish/`. git이 무시한다 |
| 검수 | Gemini가 다듬은 글이 원문과 사실이 같은지 Claude가 대조하는 것 |
| 보존 목록 | 다듬기에서 바꾸면 안 되는 표기. Must Have의 "보존 목록" 묶음 |

## 배경

- 하네스는 문서 문장 규칙([`doc-writing.md`](../../../.claude/rules/doc-writing.md))과 보고 문체 규칙([`core-reporting.md`](../../../.claude/rules/core-reporting.md))을 두고 Claude가 지키게 한다. 그래도 Claude가 쓴 글은 내부 용어가 많고 딱딱하다는 것이 사용자 판단이다
- 다른 모델이 한 번 더 읽고 고치면, 같은 모델이 스스로 고칠 때 놓치는 어색함을 잡을 수 있다. 사용자가 Gemini API 무료 등급 키를 쓰기로 했다
- 하네스는 [플러그인 배달](harness-plugin-delivery.md)로 옮기는 중이라, 지금의 복사 방식과 플러그인 방식에서 모두 돌아야 한다

### 조사로 확인한 것 (2026-10-28)

열은 확인한 사실, 이 스펙에 주는 영향, 근거 순이다.

| 사실 | 이 스펙에 주는 영향 | 근거 |
|---|---|---|
| 무료 등급에서 보낸 글과 응답은 Google이 제품과 모델 개선에 쓰고, 사람 검토자가 읽을 수 있다. 약관은 민감한 정보를 무료 등급에 보내지 말라고 한다 | 기본은 꺼 두고, 프로젝트가 직접 켤 때만 보낸다 | [Gemini API 추가 약관](https://ai.google.dev/gemini-api/terms) (2026-04-28 갱신) "Unpaid Services" |
| 무료 등급으로 쓸 수 있는 정식 모델은 `gemini-3.8-flash`, `gemini-3.6-flash`, `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`다. 2.5 계열은 예전 사용자에게만 열려 있다 | 기본 모델은 처음에 `gemini-3.8-flash`로 정했다가, 실제 호출에서 응답이 멈춰 `gemini-3.5-flash`로 바꿨다(변경 이력) | [모델 목록](https://ai.google.dev/gemini-api/docs/models) (2026-10-22) · [가격](https://ai.google.dev/gemini-api/docs/pricing) (2026-10-27) |
| 무료 한도는 모델별 숫자가 문서에 없고 AI Studio에서 프로젝트마다 본다. 하루 한도는 미국 태평양 시간 자정에 초기화된다. 한도는 키가 아니라 Google Cloud 프로젝트 단위로 걸린다 | 한도 초과는 자주 생기는 실패로 보고 작업을 막지 않는다 | [Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits) (2026-10-26) |
| 플러그인 설정(`userConfig`)에 `sensitive: true`로 받은 값은 운영체제의 보안 저장소(macOS는 키체인)에 들어가고, 훅 프로세스에만 `CLAUDE_PLUGIN_OPTION_<키>` 환경 변수로 전달된다. Claude가 Bash로 돌리는 명령에는 전달되지 않는다 | 키와 모델은 플러그인 설정이 아니라 환경 변수와 macOS 키체인에서 읽는다. 문서 스크립트와 메시지 훅이 같은 곳을 본다 | [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference) "User configuration" · "Environment variables" |
| `PreToolUse` 훅은 `permissionDecision`을 `deny`·`ask`·`allow`로 낼 수 있다. `ask`이면 사용자에게 승인 창이 뜬다 | 처음에는 이 방식으로 커밋·PR 명령을 멈춰 다듬은 글을 돌려줬다가 걷어냈다(설계 선택) | [Hooks reference](https://code.claude.com/docs/en/hooks.md) "PreToolUse decision control" |
| 백그라운드 훅(`async`·`asyncRewake`)은 명령을 멈추거나 승인 창을 띄울 수 없다. 결과는 Claude에게만 전달되고 사용자 화면에는 뜨지 않는다 | 메시지 다듬기는 백그라운드로 돌릴 수 없다. 문서도 백그라운드로 돌리지 않는다(아래 설계 선택) | 같은 문서 "Run hooks in the background" |
| 훅은 Claude의 채팅 답변을 바꿀 수 없다. `MessageDisplay`는 화면 표시만 바꾸고 대화 기록에는 원문이 남는다 | 채팅은 대상에서 뺀다 | 같은 문서 "MessageDisplay" |
| Claude에게 돌려주는 글이 길면 잘릴 수 있다. `SessionStart` 훅은 1만 자가 상한이다 | 문서 다듬기의 차이가 9,000자를 넘으면 상태 폴더에 두고 경로만 출력한다 | [플러그인 배달 스펙](harness-plugin-delivery.md) "공식 문서로 확인한 것" |

이미 있는 도구도 조사했다(2026-10-28). [im-not-ai](https://github.com/epoko77-ai/im-not-ai)처럼 한국어 AI 문체를 고치는 Claude Code 스킬은 여럿 있지만, 모두 Claude가 스스로 고치는 수동 호출 도구다. Claude가 쓴 글을 다른 모델이 다듬도록 흐름에 묶은 공개 사례는 찾지 못했다. 경로·숫자·`{{슬롯}}`을 기계로 대조하는 장치도 어느 도구에 없다. 사용자는 비교 결과를 보고 이 스펙대로 직접 만들기로 했다.

### 설계 선택 — 문서는 작성이 끝나는 시점에 한 번

문서를 다듬는 시점으로 세 가지를 검토했다.

| 방식 | 기각하거나 고른 이유 |
|---|---|
| 턴이 끝날 때마다(`Stop` 훅) | 기각. 매 턴 끝에 Gemini 응답을 기다려야 하고, 외부 호출이 늦거나 끊기면 턴이 붙잡힌다 |
| 백그라운드로 돌리고 끝나면 Claude를 깨움 | 기각. 다듬는 동안 같은 문서를 고치면 덮어쓰는 충돌이 생기고, 실패 경고가 사용자에게 보이지 않으며, 검수 턴이 대화에 따로 끼어든다 |
| 주 1회 일괄 | 기각. 문서는 쓰자마자 사람이 읽는데, 최대 일주일 동안 다듬기 전 글이 남는다 |
| **작성이 끝나는 시점에 한 번** | 채택. 사람이 처음 읽기 직전이고, 다른 편집이 없는 시점이라 충돌이 없다. 기다림은 그 시점에 한 번이다 |

### 설계 선택 — 메시지는 훅이 아니라 커밋을 묻기 직전에

처음에는 `PreToolUse` 훅이 커밋·PR 명령을 멈추고 다듬은 메시지를 Claude에게 돌려주는 방식으로 만들었다. 커밋마다 멈추고 다시 실행하는 상태 관리, 다듬지 않은 문서 알림, 트래커 명령 상수가 붙어 복잡해졌고, 사용자가 기능의 무게에 비해 지나치다고 판단해 걷어냈다(2026-10-28). 지금은 Claude가 커밋을 묻기 직전에 메시지를 `message`로 다듬고 검수한 뒤, 다듬은 커밋 목록으로 한 번 승인받는다. 다듬기를 강제하는 장치는 없다 — 빠뜨렸는지는 승인 때 보이는 메시지 목록에서 드러난다.

## 요구사항

### 흐름

1. Claude가 남는 글을 쓴다
2. Gemini가 다듬는다
3. Claude가 원문과 다듬은 글을 대조해 사실이 같은지 검수한다
4. 틀린 곳만 Claude가 최소한으로 고친다. 이 수정은 다시 다듬지 않는다
5. 확정한다. 문서는 평소처럼 diff로 확인한다. 커밋과 PR은 Claude가 "다듬기 작업을 전부 마쳤어요. 커밋할까요?"라고 커밋 목록과 함께 한 번 묻고, 사용자가 승인하면 목록대로 커밋한다

### Must Have

**켜기와 키**

- [ ] 기본은 꺼져 있다. 키가 있고, 그 프로젝트 설정에서 "Gemini 다듬기"를 켰을 때만 Gemini에 글을 보낸다
- [ ] 플래그가 꺼져 있으면 아무것도 보내지 않고 조용히 끝난다. 플래그는 켰는데 키가 없으면 아무것도 보내지 않고 "실패" 묶음대로 경고 한 줄을 낸다
- [ ] 프로젝트 설정은 `harness-map.md` 능력 플래그 "Gemini 다듬기"다. 스킬은 이 플래그를 읽는다. 스크립트는 map을 읽지 못하므로 프로젝트 루트 `harness.conf`의 `POLISH_ENABLED=1`을 짝으로 둔다(`.claude/rules/README.md` "훅 상수와 짝"에 추가). 스크립트의 같은 이름 상수는 배달 기본값 `0`이다 — 원본 저장소의 켜짐이 복사본에 실려, `init-harness` 없이 복사한 프로젝트의 글이 밖으로 나가는 것을 막는다. 루트는 복사되지 않는 자리다(`dev.conf`와 같은 이유). 플러그인 방식에서는 [플러그인 배달 스펙](harness-plugin-delivery.md)의 프로젝트 설정 파일에 같은 값을 둔다
- [ ] `init-harness`가 하네스를 붙일 때 이 플래그를 묻는다. 권장 값은 ❌이고, 무료 등급 약관(보낸 글을 Google이 학습에 쓸 수 있음)을 함께 보여 준다. 이 저장소는 ☑로 둔다
- [ ] 키는 파일에 쓰지 않는다. 스크립트는 키를 이 순서로 찾는다: 환경 변수 `GEMINI_API_KEY` → (macOS면) 키체인 항목 `gemini-api-key`. 복사 방식과 플러그인 방식이 같다. 키는 컴퓨터마다 사용자가 직접 한 번 넣는다
- [ ] 플러그인 설정(`userConfig`)은 쓰지 않는다. 그 값은 훅에만 전달되고 Claude가 돌리는 스크립트에는 전달되지 않기 때문이다
- [ ] 모델은 기본 `gemini-3.5-flash`이고, 환경 변수 `GEMINI_MODEL`로 바꾼다. `gemini-flash-latest` 같은 자동 최신 별칭은 기본값으로 쓰지 않는다
- [ ] 기본 모델이 503(사용량 몰림)이면 대체 모델로 한 번만 더 시도한다. 대체 모델은 `gemini-3.5-flash-lite`이고 환경 변수 `GEMINI_FALLBACK_MODEL`로 바꾼다. 빈 값이면 다시 시도하지 않는다. 한도 초과(429)와 시간 초과는 다시 시도하지 않는다

**대상**

- [ ] 사람용 문서는 `{{문서 루트}}` 아래 마크다운 전부와 저장소 루트 `README.md`, `.github/` 아래 마크다운이다
- [ ] `{{문서 루트}}/templates/`는 뺀다. 안내문과 섹션 이름이 새 문서의 기준이라 문장이 바뀌면 안 된다
- [ ] Claude가 읽는 글은 뺀다. `.claude/` 전체, `AGENTS.md`, `CLAUDE.md`, `examples/`가 여기에 든다
- [ ] 남는 글 중 명령으로 만드는 것은 커밋 메시지와 PR·이슈의 제목·본문·댓글이다. 트래커마다 만드는 수단은 트래커 안내 스킬이 갖는다([이슈 트래커 중립화](issue-tracker-neutral.md))
- [ ] 채팅 답변은 대상이 아니다

**문서 다듬기 — 작성이 끝나는 시점에**

- [ ] 작성이 끝나는 시점은 아래 셋이다. 해당 스킬의 그 단계에 "다듬기 → 검수 → 확정"을 한 단계로 넣는다

| 시점 | 문서 | 넣을 곳 |
|---|---|---|
| 승인 요청 직전 | 기능 스펙, 아키텍처 감사, 아키텍처 결정(ADR) | `write-spec` 9단계 · `refactor-safely` 2단계 · ADR은 `verify-work` 마무리와 같은 방식으로 승인 요청 전에 |
| 완료 보고 직전 | 그 작업에서 고친 나머지 사람용 문서 — 작업 보고서, 리팩터 반영 이력, 현재동작 요약, README, 안 하기로 한 것 등 | `verify-work` 마무리 — 그 단계의 문서(보고서·반영 이력)를 다 쓴 뒤, 완료 보고 전에 |
| 회고 기록 직후 | 회고 장부 | `improve-harness` 마지막 단계 |

- [ ] 수정 요청을 받아 고친 뒤 다시 승인을 요청하면, 그때 바뀐 문단만 다시 다듬는다. 승인 뒤 바뀌는 상태 줄과 체크박스는 다듬지 않는다
- [ ] Claude가 `scripts/polish-with-gemini.sh docs <파일…>`을 돌린다. 스크립트는 기준판과 비교해 바뀐 문단만 보내고, 새 문서는 전체를 보낸다. 바뀐 문단의 앞뒤 문단은 말투를 맞추는 참고로만 보내고 고치지 않게 한다
- [ ] 문단은 빈 줄로 나눈다. 표와 목록은 한 덩어리로 다루고, 코드 블록과 문서 머리의 메타데이터는 보내지 않는다
- [ ] 스크립트는 보존 목록 대조를 통과한 문단만 파일에 반영하고, 원문과의 차이를 출력한다. 9,000자를 넘으면 상태 폴더에 차이를 두고 경로만 출력한다
- [ ] Claude가 검수와 최소 수정을 마치면 `scripts/polish-with-gemini.sh done <파일…>`로 지금 판을 기준판으로 기록한다. 그래서 검수 중의 수정은 다음에 다시 다듬지 않는다

**메시지 다듬기 — 커밋을 묻기 직전에**

- [ ] Claude가 작업을 끝내고 커밋 분할안을 만들면, 각 메시지를 `scripts/polish-with-gemini.sh message`로 다듬고 검수한다(`verify-work` 마무리)
- [ ] 다 마치면 다듬은 커밋 목록과 함께 "다듬기 작업을 전부 마쳤어요. 커밋할까요?"라고 한 번 묻는다. 승인되면 목록대로 커밋하고, 커밋마다 따로 묻지 않는다
- [ ] PR·이슈 글은 만들기 전에 같은 방식으로 다듬는다(트래커 안내 스킬)
- [ ] 강제하는 훅은 두지 않는다. Claude가 빠뜨리면 다듬지 않은 메시지가 승인 목록에 그대로 보인다

**다듬기 기준**

- [ ] 스크립트가 실행될 때마다 `doc-writing.md` 3절(문장), `core-reporting.md`, `scripts/doc-style-patterns.txt`를 읽어 Gemini에 기준으로 보낸다. 기준 글을 따로 만들지 않는다

## 테스트 먼저 지점

Must 항목마다 실패하는 테스트를 먼저 쓸지 제안한다. G2에서 사람이 고친다.

| Must 항목 | 테스트 먼저 | 근거 |
|---|---|---|
| 플래그가 꺼졌거나 키가 없으면 아무것도 보내지 않는다 | 테스트 먼저 | 외부로 글이 나가는지가 갈린다(개인정보 통제 영역). 판정 순서를 바꾸는 변경이 깨뜨린다 |
| 대상 경로 판정(템플릿·`.claude/`·`AGENTS.md` 제외) | 테스트 먼저 | 보내면 안 되는 글이 나간다. 경로 패턴 변경이 깨뜨린다 |
| 보존 목록 기계 대조 | 테스트 먼저 | 문서 사실이 몰래 바뀌는 것을 막는 장치다(`core-guardrails.md` §1). 대조 규칙 변경이 깨뜨린다 |
| 실패하면 경고하고 진행 | 테스트 먼저 | 장애 처리(통제 영역). 막아 버리면 한도 초과 하루 동안 작업이 멈춘다 |
| `done` 뒤의 수정은 다음에 다시 다듬지 않는다 | 테스트 먼저 | 기준판 갱신이 틀리면 검수 수정이 계속 다시 다듬어진다 |
| 키가 출력과 파일에 남지 않는다 | 테스트 먼저 | 시크릿 노출(통제 영역) |
| 바뀐 문단 추출과 코드 블록 제외 | 아님 | 통제 영역이 아니다. 평소대로 케이스로 확인한다 |
| 스킬 단계 추가·플래그·`init-harness` 질문·문서 반영 | 아님 | 단순 연결 |

테스트는 네트워크 없이 돈다. Gemini 주소는 스크립트의 상수 `GEMINI_ENDPOINT`로 두고, `scripts/hook-cases.txt`의 상수 바꾸기(`;GEMINI_ENDPOINT=…`)로 `file://` 가짜 응답을 가리키게 한다.

## API / 인터페이스

API 없음 — 외부 클라이언트와의 계약이 없다. 하네스 안의 인터페이스는 아래와 같다.

| 구성 요소 | 부르는 곳 | 하는 일 |
|---|---|---|
| `scripts/polish-with-gemini.sh docs <파일…>` | 스킬 단계에서 Claude가 | 기준판과 비교해 바뀐 문단을 다듬고, 대조를 통과한 문단을 반영한 뒤 차이를 출력 |
| `scripts/polish-with-gemini.sh done <파일…>` | 검수를 마친 Claude가 | 지금 판을 기준판으로 기록 |
| `scripts/polish-with-gemini.sh message` | 커밋을 묻기 직전·PR·이슈를 만들기 전에 Claude가 | 표준 입력의 메시지를 다듬어 출력 |
| `scripts/polish-with-gemini.sh enabled` | 필요할 때 Claude가 | 플래그가 켜졌는지만 알린다 |

**종료 코드와 출력**

| 명령 | 결과 |
|---|---|
| `enabled` | 켜짐 0 · 꺼짐 2 |
| `docs` · `done` | 항상 0(사용법 오류만 2). 꺼져 있으면 출력이 없다. 대상이 아닌 파일은 `건너뜀(대상 아님): <경로>`. 실패하면 `다듬기 건너뜀(<원인>)` 한 줄을 내고 파일을 바꾸지 않는다 |
| `message` | 표준 입력 JSON `{"kind": "commit"·"pr"·"issue", "fields": {이름: 글}}` → 표준 출력 JSON `{"fields": {…}}`. 성공 0 · 실패 1(출력은 원인 한 줄) · 꺼짐 2(출력 없음) |

**상수** — 훅 상수처럼 본문에 직접 적는다. 테스트는 `scripts/hook-cases.txt`의 상수 바꾸기로 값을 바꾼다.

| 상수 | 기본값 | 뜻 |
|---|---|---|
| `POLISH_ENABLED` | `0` | 배달 기본값. 프로젝트 루트 `harness.conf`의 `POLISH_ENABLED`가 있으면 그 값이 앞선다(이 저장소는 `1`) |
| `DOC_ROOT` | `docs` | `{{문서 루트}}`의 짝 |
| `ROOT` | git 최상위 폴더 | 경로 판정과 기준판의 기준 |
| `STATE_DIR` | `.claude/polish` | 상태 폴더(`ROOT` 기준) |
| `GEMINI_ENDPOINT` | Gemini `generateContent` 주소, 모델 자리는 `{model}` | 테스트는 `file://` 가짜 응답을 가리킨다 |
| `DEFAULT_MODEL` | `gemini-3.5-flash` | 환경 변수 `GEMINI_MODEL`이 없을 때 |
| `FALLBACK_MODEL` | `gemini-3.5-flash-lite` | 기본 모델이 503(사용량 몰림)이면 한 번만 더 시도할 모델. 환경 변수 `GEMINI_FALLBACK_MODEL`로 바꾸고, 빈 값이면 다시 시도하지 않는다 |
| `TIMEOUT_DOCS` · `TIMEOUT_MESSAGE` | `60` · `30` | 초 |
| `KEY_ENV_NAME` · `KEYCHAIN_SERVICE` | `GEMINI_API_KEY` · `gemini-api-key` | 키를 찾는 환경 변수와 키체인 항목 |

Gemini에는 JSON 응답을 요청하고, 응답 글은 `{"items": [{"id": …, "text": …}]}`이다. 문서 문단의 `id`는 `<경로>:<문단 번호>`(0부터, 빈 줄로 나눈 순서), 메시지는 필드 이름이다.

## 토큰 비용

`.claude/rules/README.md` 유지보수 체크리스트의 세 층으로 적고, 실행 비용은 Claude와 Gemini로 나눈다. 바이트는 구현 뒤 실측해 고친다.

| 층 | 늘어나는 것 | 크기(추정) |
|---|---|---|
| 항상 실리는 글 | `harness-map.md` 플래그 표 한 행 | 약 150B |
| 호출될 때 실리는 글 | 스킬 4개 본문에 한 줄씩, `.claude/rules/README.md` 목록과 짝(`.claude/`를 열 때만) | 약 1KB |
| 실행 비용 — Claude | 검수할 차이(9,000자 이하, 넘으면 경로만)와 메시지마다 다듬은 글 몇백 자 | 작성이 끝나는 시점과 커밋을 묻기 직전에만 |
| 실행 비용 — Gemini | 기준 글(규칙 3개 약 10KB)과 보낼 글. 시점마다 한 요청, 메시지마다 한 요청 | 무료 등급 한도 안 |

## 검증 시나리오

### 정상

- [ ] 플래그 ☑와 키가 있을 때 스펙 초안을 쓰고 승인을 요청하기 직전 스크립트를 돌리면, 바뀐 문단만 다듬어지고 차이가 출력된다
- [ ] Claude가 검수하고 숫자 하나를 원문대로 되돌린 뒤 `done`을 돌리면, 다음 실행에서 그 문단은 보내지 않는다
- [ ] 수정 요청으로 한 문단을 고치고 다시 돌리면 그 문단만 보낸다
- [ ] 새 문서는 코드 블록을 뺀 전체가 다듬어진다
- [ ] 커밋 메시지 초안을 `message`로 보내면 다듬은 메시지가 돌아오고, 머리말·이슈 연결·끝 줄은 그대로다

### 엣지 · 실패

- [ ] 플래그 ❌이면 스크립트가 아무것도 보내지 않는다
- [ ] 플래그 ☑인데 키가 없으면 한 줄 경고만 나오고 그대로 진행한다
- [ ] `.claude/rules/`, `AGENTS.md`, `docs/templates/` 파일을 넘기면 다듬지 않고 건너뛴다
- [ ] Gemini가 경로나 `{{슬롯}}`을 바꾼 문단은 원문이 유지되고 차이에 나오지 않는다
- [ ] 가짜 응답이 한도 초과(429)이면 경고 한 줄과 함께 원문으로 진행하고, 기준판은 그대로다
- [ ] 가짜 응답이 깨진 JSON이면 같은 방식으로 진행한다
- [ ] 실패 경고, 상태 폴더, 출력 어디에도 키 문자열이 없다

### 수동 / 통합

- [ ] 실제 키로 이 저장소 문서 하나와 커밋 하나를 다듬어 보고, 결과를 사용자가 확인한다
- [ ] 데스크톱 앱 세션에서 환경 변수가 없을 때 키체인으로 키를 읽는지 확인한다
