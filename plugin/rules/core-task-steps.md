# Core — 워크플로 (작업 선택·승인·검증)

요청의 영향으로 작업 규모를 정한 뒤 필요한 절차만 읽는다. 작업 도중 멈출 조건은 `core-stop-conditions.md`, 사용자 승인이 필요한 결정은 `core-approval-triggers.md`를 따른다. 명령과 경로는 세션의 하네스 설정 값 표에서 찾는다.

## 진입 — 작업과 규모

| 규모 | 판단 기준 | 진행 |
|---|---|---|
| **S 단순** | 오타·표시 문구·로그처럼 영향이 국소적이고 통제 영역에 닿지 않는다. 같은 문구가 여러 파일에 있어도 해당한다 | 대상 파일과 직접 관련된 테스트를 확인하고 수정한다. 코드 편집 후 `{{테스트 명령}}`을 실행한다. 프로젝트의 필수 검사는 문서 작업에도 적용한다 |
| **L 강화** | 외부 API 계약·데이터 스키마·인증·과금·개인정보·장애 복구가 바뀌거나 여러 구성 요소의 동작이 함께 바뀐다 | G2 승인, 구현, G3 독립 리뷰와 검증, G4 결과 기록 |
| **M 표준** | 나머지 구현 변경 | 해당 트랙, G2, 구현, G3, G4 |

- **A 기능** — 제품 범위나 외부 계약·데이터·배포 동작을 바꾸면 `write-spec`으로 완료 기준을 정하고 승인받는다. 이미 승인된 스펙은 재사용한다. 단순 구현은 필요한 경우에만 `{{제품 범위}}`를 본다.
- **B 감사·리팩터** — `refactor-safely`로 작업 단위를 정한다. 점검 요청은 발견 사항과 근거를 보고하면 끝난다.
- **C 버그** — `fix-bug`로 증상을 재현하고 원인과 수정 범위를 확인한다.
- **D 설치·재설정** — `init-harness`로 실측하고 승인된 설정만 적용한다. 애플리케이션 코드는 보존한다.

읽기 전용 질문이나 작은 수정은 대상과 직접 관련된 근거부터 확인한다. 연결된 이슈가 있으면 그 범위·완료 기준을 확인한다. 설계 경계는 `{{아키텍처 개요}}`, 우선순위는 `{{우선순위 SSOT}}`, 외부 연동은 `{{클라이언트 전제}}`, 과거 선택은 `{{결정 기록}}`에서 필요한 부분만 읽는다.

## G1. 외부 근거가 필요할 때

설치한 버전과 `{{의존성 조회}}`로 로컬 사실을 확인한 뒤 해당 버전의 공식 문서를 본다. 버전 차이·상충하는 근거·여러 대안의 조사가 필요할 때 `researcher`에게 질문과 범위를 넘긴다.

## G2. 승인

기능은 스펙, 리팩터는 감사의 A/B 항목, 버그는 원인과 수정 범위, 설치는 실측값을 승인받는다. 통제 영역의 미정 사항은 `clarify-requirements`로 확인한다. 같은 범위를 이미 승인받았으면 그 결정에서 이어간다.

작업 중 지켜야 할 조건과 확인 방법을 정한다. 기능은 기존 계약·테스트, 리팩터는 관찰 가능한 동작, 버그는 관련 없는 기존 동작, 설치는 앱 코드 보존을 확인한다. 다단계 변경이면 대상 파일과 단계별 검증을 정한다. 브랜치는 `{{기본 브랜치}}`와 `{{브랜치명 형식}}`을 따른다.

## 구현

요청 범위 안에서 프로젝트 관례를 따른다. 읽기 전용 역할에 플러그인 도구가 필요하면 현재 설치 경로도 넘긴다. 빌드·테스트·실행은 플러그인의 `scripts/dev.sh`와 프로젝트 `dev.conf`를 쓴다. 버그와 승인된 테스트 우선 지점은 첫 편집 전에 `test-first`를 연다. 새 테스트는 `core-testing.md`, 주석은 `core-code-comments.md`를 따른다. 역할을 분담할 때는 맡은 질문·대상 경로·지켜야 할 조건만 전달한다.

## G3. 검증

M·L은 `verify-work`를 따른다. 마지막 코드 편집 뒤 실제 전체 테스트 결과를 확인한다. 미실행·실패 검사는 이유와 함께 보고한다. 보안·아키텍처가 바뀌면 `{{현재동작 요약}}`의 갱신 여부를 확인한다.

## G4. 보고와 커밋

검증 결과와 목적별 커밋 분할안(최대 5개)을 제시한다. 형식은 `{{Git 컨벤션 SSOT}}` 또는 `{{커밋 메시지 형식}}`·`{{머지 방식}}`·`{{이슈 연결}}`을 따른다. 커밋·PR·머지는 Claude의 승인 창 또는 Codex의 명시적 확인 뒤에 실행한다. 이슈·브랜치 생성도 먼저 확인한다. 긴 작업이 중단될 때만 기존 스펙이나 감사 문서에 승인 범위, 마지막 검사와 다음 행동을 남긴다.
