# 안 하기로 한 것 (Out of Scope)

이 하네스가 **검토한 뒤 채택하지 않은 장치와 결정**을 이유와 함께 모아 둔 목록이다. 같은 논쟁이 반복되는 것을 막는 장치다 — 새 도구를 제안하기 전에 여기서 이미 기각된 것인지 먼저 본다. 상황이 바뀌어 다시 검토하면 이 표의 행을 고치고 근거를 갱신한다. 행마다 판정 기준은 둘 중 하나다 — 하네스 장치는 부품성 원칙(장치 하나는 bash 하나 + 데이터 파일 하나 · 새 개념은 기존 개념을 대체해야 함 · 스택에 묶이는 것은 팩으로), 서드파티 도구는 아래 "도입 기준".

## 도입 기준

서드파티 플러그인·도구를 들이기 전에 본다. 우선순위는 Claude Code 기본 기능 → 서드파티 플러그인 → 프로젝트 문서(`.claude/rules/`·`.claude/skills/`)이고, 위 단계로 필요가 채워지면 아래로 내려가지 않는다. 설치는 의존성 추가라 사용자 승인 없이 하지 않는다(`core-gates.md` §2).

- **채택 조건(전부 만족):** 문서가 더 단순해진다 · 반복 작업이 사라진다 · 유지보수성이 오른다 · 토큰 또는 작업량이 준다
- **배제 조건(하나라도):** 기능이 있다는 이유만으로 쓴다 · 기존 문서보다 복잡해진다 · 토큰만 는다 · 기본 기능으로 충분하다

## 언제 이 문서를 보는가

- 서드파티 플러그인·새 훅·새 스킬·새 디렉터리 구조를 제안하려 할 때
- "왜 X를 안 쓰나"라는 질문을 받았을 때
