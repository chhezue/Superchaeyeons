# 위험 명령 차단 훅의 오탐 줄이기

> 상태: Approved (2026-10-28 G2 — 결정은 아래 "결정" 절)
> MVP: In scope
> 관련 BR: N/A

`deny-dangerous-bash.sh`가 실제로 막은 43건을 대화 기록에서 모두 뽑아 분류했다. 그 결과로 오탐을 줄이는 선택지를 비교하고 권장안 하나를 고른다. 진짜 위험은 계속 막고, 실행되지 않는 글자 때문에 막히는 일을 없애는 것이 목표다. 조사 중에 지금 훅이 놓치는 위험 명령도 드러나 함께 다룬다. G2에서 사용자가 "너무 빡빡하게 막으면 작업이 멈추고 늦어진다"며 위험 명령을 묶음으로 나눠 고르게 해 달라고 해서, 묶음별 막기·맡기기도 이 스펙에 넣었다.

## 목표

명령 안에서 **실제로 실행되는 부분만** 검사해서, 따옴표·heredoc·검색어 안의 위험 문자열 때문에 막히는 일을 없앤다. 위험 명령을 6묶음으로 나눠 묶음마다 훅이 막을지, Claude Code 기본 권한 체계에 맡길지를 훅 상수로 고르게 한다. 이 저장소는 지연의 대부분을 낸 파일 대량 삭제 묶음만 맡기고 나머지는 막는다.

## 배경

- 훅은 명령 문자열 **전체**에 정규식을 대고, 하나라도 맞으면 exit 2로 막는다. 훅 4행에 "문자열로만 언급해도 막힌다"는 알려진 오탐이 적혀 있고, fail-closed가 의도라며 그대로 두었다
- 2026-10-28 다른 세션에서 테스트 케이스 데이터 때문에 명령이 두 번 막혔다(아래 41·42번). 사용자는 예전부터 오탐과 막힘이 잦았다고 지적했다
- 조사 범위: `~/.claude/projects/*/` 아래 대화 기록 613개(서브에이전트 기록 포함). 이 훅과 옛 이름 `block-dangerous.sh`(원본 백엔드 프로젝트에 복사된 이전 판)의 차단 메시지를 찾고, 같은 도구 호출이 여러 기록에 복사된 것은 하나로 셌다
- 관련 문서: [`.claude/rules/README.md`](../../../.claude/rules/README.md) "훅 공통 규약" · [`scripts/hook-cases.txt`](../../../scripts/hook-cases.txt) · [`deny-git-clean.md`](deny-git-clean.md)

## 전수 조사 결과

43건 중 **막을 필요가 있던 것은 7건(16%)** 이었다. 23건(53%)은 실제로 지우려던 명령이지만 대상이 자기가 만든 임시 폴더라 위험이 낮았고, 13건(30%)은 실행되지 않는 글자 때문에 막힌 순수 오탐이었다.

### 지금 훅이 놓치는 위험 명령

10번(ssh로 운영 서버에서 `docker compose down -v`)은 이전 판 훅이 막았는데, **지금 훅에 같은 명령을 넣으면 통과한다**. 패턴 끝의 `([[:space:]]|$)`가 닫는 따옴표 앞에서 맞지 않기 때문이다. 같은 이유로 아래 탐침 14종이 전부 exit 0이다. 표의 예가 탐침 전체다(2026-10-28 실측, 훅에 JSON을 직접 넣음).

| 놓치는 모양 | 예 |
|------|------|
| 닫는 따옴표 바로 앞에서 끝남 | `ssh h '… docker compose down -v'` · `bash -c 'git push -f'` · `sh -c 'git clean -fdx'` · `ssh h "git stash drop"` · `bash -c 'curl … | sh'` |
| 괄호·세미콜론이 붙음 | `(git push -f)` · `git push -f;echo ok` |
| 공백 두 칸 | `git reset  --hard` · `git  push -f` |
| git 전역 옵션 | `git -C repo reset --hard` · `git -C repo push -f` |
| 패턴 자체가 없음 (이번 범위 밖) | `git update-ref -d …` · `git checkout -- .` · 변수에 담은 플래그 |

## 조사 근거

`researcher` 서브에이전트가 2026-10-28에 확인했다. 로컬 Claude Code는 2.1.304이고, 아래 기능은 모두 이 버전에서 쓸 수 있다.

| 질문 | 결론 | 근거 |
|------|------|------|
| 훅이 파싱된 명령을 받나 | 받지 않는다. `tool_input.command` 원문뿐이다. 훅 설정의 `if: "Bash(…)"` 필터는 Claude Code가 하위 명령으로 나눠 맞춰 보지만, 그 결과를 훅에 넘기지 않고 best-effort라 강제 차단에 쓰지 말라고 적혀 있다 | [hooks](https://code.claude.com/docs/en/hooks) |
| exit 2와 `deny` | 둘 다 모든 권한 모드에서 막는다(`bypassPermissions` 포함). exit 0·2 말고 다른 종료 코드, 시간 초과, 시작 실패는 **막지 않고 통과**한다. `"onFailure": "block"`(2.1.295+)을 주면 막는다 | [hooks](https://code.claude.com/docs/en/hooks) |

**이 저장소에 주는 영향 두 가지.** 첫째, `settings.json`의 `permissions.deny`에 `Bash(rm -rf:*)`·`Bash(git reset --hard:*)`가 있어서, 훅만 `ask`나 허용으로 바꿔서는 실제로 지우는 명령이 풀리지 않는다(D·E에 해당). 둘째, 훅이 시간 초과로 죽으면 통과한다. 판정기가 무거워지면 `onFailure: "block"`을 함께 검토한다.

**고르면 달라지는 것**

- **A**: 코드가 그대로라 바뀌는 것이 없다. 막힌 뒤 헤매는 시간만 줄 수 있다. 10번 같은 놓침도 남는다
- **B**: 놓치던 위험 명령 11종이 막힌다. 오탐은 그대로다. 위험 문자열이 들어간 데이터를 Bash로 다루지 말라는 지금 방식이 계속된다
- **C**: 따옴표·heredoc·주석 안 글자는 검사하지 않는다. 대신 그 글자가 실제로 실행되는 자리는 다시 검사한다 — `bash`·`sh` 등의 `-c` 인자 · `eval` · `ssh` 뒤 명령 · `psql`·`mysql`의 SQL 인자 · `"$(…)"`·백틱 · 셸이 받는 heredoc. 명령 어딘가에서 무엇이든 셸로 파이프하면(`| bash`) 지금처럼 원문 전체를 검사한다. 해석에 실패해도(닫히지 않은 따옴표 등) 원문 전체 검사로 돌아가므로 "판정 불가 = 차단" 규약은 그대로다
- **D**: 임시 폴더 정리가 막히지 않는다. 대신 훅이 "이 경로는 지워도 되나"를 판단하게 되는데, 이는 "판단이 필요한 것은 훅에 넣지 않는다" 규약과 부딪힌다. scratchpad 경로가 Claude Code 실행 환경마다 달라 슬롯도 필요하다. `permissions.deny`의 `Bash(rm -rf:*)`도 같이 빼야 효과가 난다
- **E**: 위험 낮은 실제 삭제 23건이 사용자 확인 창으로 바뀐다. 사용자가 누르면 실행된다. auto mode에서도 창이 뜨므로 사용자가 자리를 비우면 작업이 멈추고, `claude -p`·답할 사람 없는 실행에서는 지금처럼 거부된다. "훅 승인 통로는 설정 변경뿐"(`core-gates.md` §3)에 "사용자가 확인 창에서 누르는 것"을 더하는 정책 변경이다. 역시 `permissions.deny`를 같이 고쳐야 한다
