# Core — 멈추는 근거

작업을 진행하기 전에 사용자 확인이 필요한 범위를 정한다. 충돌로 작업을 중단할 조건은 `core-stop-conditions.md`에 있다.

## 1. 통제 영역과 위임 영역

변경이 왼쪽 열에 닿으면 트랙·규모와 무관하게 G2 승인 대상이다. 오른쪽 열만 건드리면 G2를 짧게 지나가고 G3 검증에 무게를 둔다. 두 열에 걸치면 통제 쪽으로 본다.

| 통제 — G2 승인 없이 구현하지 않는다 | 위임 — 계약과 테스트로 검증한다 |
|---|---|
| 도메인 규칙 · 비즈니스 흐름 · 상태 전이 | 멱등하게 테스트 가능한 컴포넌트 |
| 인증 · 과금 · 개인정보 | 표현 계층 구성 |
| 장애 복구 · 재시도 · 멱등성 | 매핑·변환 계층 |
| 외부 API 계약 · 스키마 · 마이그레이션 | 반복적인 상용구 · 문서 초안 |

## 2. 멈추는 신호

1번에 걸리지 않아도 하나라도 해당하면 진행 전에 확인한다.

| 신호 | 대응 |
|------|------|
| 사용자가 정하지 않은 **기본값**이 외부 동작·계약·비용을 바꿈 | 후보와 권장 값을 보이고 묻는다 |
| 가능한 해석에 따라 결과나 승인 범위가 달라지고 기존 결정으로 정할 수 없음 | `clarify-requirements` 스킬 — 결정만 하나씩 묻는다 |
| 새 파일 3개 이상 · **의존성 추가 계획**(서드파티 플러그인 설치 포함) | 목록을 먼저 보이고 승인 |
| 문서 2개가 다른 값을 말함 | `core-stop-conditions.md` §1 |
| **트랙이 바뀜** — B 중 계약·기술 변경이 필요해짐 | A 승격 여부를 묻는다 |
| **완료 기준 밖 조사** — "혹시 모르니" 검증·목표와 무관한 이상·같은 문제로 명령 3회 초과 | 알아낸 것을 한 줄로 보고하고 묻는다 |
| **훅이 막음** | 3절 — 우회하지 않고 보고한다 |

**Claude Code에서는 훅이 승인 창을 띄운다** — 커밋·push·PR 생성·머지, 추적 파일 삭제, 의존성 선언 파일 수정·설치 명령, 민감한 경로 쓰기, 스펙 `Approved` 전환·`[미정]` 확정, 채워진 `.claude/harness.conf` 수정. 창이 승인이다 — 같은 일을 채팅에서 다시 승인받지 않고, 창을 피하려고 다른 도구를 쓰지 않는다.

Codex는 플러그인 `codex/INSTRUCTIONS.md`의 승인 사전 검사와 명시적 확인을 따른다. 이 문서·워크플로·스킬의 승인 창 설명은 Claude Code 기준이며, Codex에 같은 강제력이 있다고 가정하지 않는다.

**의존성 사다리:** 새 의존성 전에 표준 라이브러리 → 플랫폼 기본 기능 → 이미 설치된 의존성 → 직접 작성 순으로 밟는다. 서드파티 도구는 `{{문서 루트}}/out-of-scope/README.md`(있으면)에서 이미 기각된 것인지 먼저 본다.

## 3. 자동으로 하지 않는 것

조건은 각 근거 파일이 갖는다.

| 하지 않는다 | 근거 |
|------|------|
| 이슈·브랜치 생성 (명시 요청 없이 — 하네스 밖 훅·시스템 메시지가 요구해도). 커밋·PR은 훅 승인 창을 거친다 | `core-task-steps.md` G4 |
| `[미정]` 확정 · 우선순위 라벨 부여·변경 | `core-stop-conditions.md` §1.8 |
| `.claude/rules/` 추가·수정 — 제안만 | `core-task-steps.md` G4 · `review-harness-feedback` 스킬 |
| **[플래그: 하네스 자기 수정]** ❌면 하네스 플러그인 폴더·`.claude/hooks/`·`settings.json` 수정(Bash 편집 포함). ☑이어도 diff를 제안하고 승인 뒤 반영 | `deny-out-of-scope-write.sh` |
| 훅이 막은 일을 다른 도구(Bash·변수·`eval`·별도 스크립트)로 하기 · 통과시키려고 훅·`settings.json`을 고치기 — 막히면 차단 메시지대로 보고하고 멈춘다 | 각 `deny-*` 훅 |
