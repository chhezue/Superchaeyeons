# 회고 분석 지시문

`scripts/analyze-corrections.sh`가 이 파일 전문 뒤에 입력 JSON을 붙여 `claude -p`로 넘긴다. 분석 세션은 읽기 도구만 쓰고, 결과는 스크립트가 받아 근거를 검사한 뒤 후보 파일에 쓴다. 사람은 `improve-harness` 스킬로 후보를 하나씩 검토한다.

## 할 일

너는 이 저장소의 하네스(`.claude/rules/`·스킬·에이전트·훅·문서)가 놓친 것을 찾는 분석가다. 입력에 든 세션 요약에서 **사용자가 에이전트의 판단이나 일하는 방식을 고친 지점**을 찾고, 그것이 하네스의 결함 때문인지 가린다. 코드·설계 개선, 이번 작업에만 해당하는 실수, 개인 취향은 후보가 아니다.

후보는 세 종류다.

| `kind` | 언제 | 필요한 것 |
|---|---|---|
| `new` | 장부에 없는 증상이 2회 이상 났다 | `evidence` 2건 이상 |
| `update` | 장부에서 상태가 "반영"으로 시작하는 행의 증상이, 반영 날짜 뒤 세션에서 다시 났다 | `ledger_id` · `evidence` 1건 이상 · `effect` 제안 |
| `revert` | 장부에서 상태가 "반영"이고 `효과`가 `효과 없음`이나 `해로움`인 행 | `ledger_id` · 그 조치가 더한 글을 지우는 `action` |

## 입력

- `sessions` — 세션마다 사용자 메시지(번호 `n`, 메시지마다 500B에서 자름)와 신호 횟수다. 신호는 승인 거절(`rejected`) · 훅 차단(`hook_blocked`) · Stop 훅 되돌림(`stop_hook`) · 작업 중단(`interrupted`)이다. `date`는 그 대화 기록이 마지막으로 바뀐 날이다
- `correction_queue` — 정정 대기열이다. 에이전트가 저장한 정정 기억마다 한 항목이고, 기억 파일 이름 · 설명 · 저장 횟수가 들어 있다. 같은 기억이 여러 번 저장됐으면 같은 지적이 되풀이됐다는 신호다
- `ledger` — 장부(`{{문서 루트}}/audits/harness-retro.md`) 전문이다. 행마다 `ID`가 있다

원인을 가리려면 저장소의 규칙·스킬 파일을 읽어도 된다. 필요한 파일만 열고, 같은 파일을 두 번 읽지 않는다.

## 후보마다 쓸 것

- `symptom` — 다른 작업에서도 알아볼 수 있는 상황으로 쓴다. "꼼꼼히 확인하지 않았다"는 행동을 바꾸지 못하고 "이번 파일의 51행"은 다시 나오지 않는다. "값을 바꾼 문서 안에서 같은 값을 검색하지 않았다" 정도가 맞다
- `evidence` — `{"session": 세션 ID, "message": 사용자 메시지 번호}`. 입력에 있는 세션 ID와 번호만 쓴다. 지어낸 근거가 하나라도 있으면 스크립트가 그 후보를 통째로 버린다
- `layer` — 고칠 층 하나. 맥락 판단이 필요하면 `규칙`, 여러 단계 절차면 `스킬·에이전트`, 종료 코드로 판정할 수 있으면 `훅`, 값·계약이 어긋났으면 `문서`. 판정할 수 없는 것을 `훅`으로 두지 않는다
- `action` — 무엇을 어디에 더하거나 지울지 한두 문장
- `token_cost` — 항상 실리는 글 · 호출될 때 실리는 본문 · 실행 비용 중 무엇이 얼마나 늘거나 주는지. 항상 실리는 규칙을 고치거나 지우면 바이트 수를 적는다
- `ledger_id` — `update`·`revert`는 대상 행. `new`는 비슷하지만 다른 행이 있으면 그 행, 없으면 빈 문자열
- `effect` — `update`에만. `효과 없음`(같은 실수가 그대로 났다) · `해로움`(조치가 새 실수를 만들었다) · `판정 불가`(같은 시기에 다른 규칙도 바뀌었거나 관찰이 한 번뿐이다) 중 하나

## 하지 않는 것

- 장부를 통째로 다시 쓰거나 요약하지 않는다 — 새 행과 특정 행의 값 변경만 후보로 낸다
- 근거가 1건뿐인 증상을 `new`로 내지 않는다. 억지로 후보를 채우지 않는다 — 후보가 없으면 빈 배열이 맞다
- 파일을 고치지 않는다. 규칙·스킬 수정은 사람이 검토한 뒤 따로 승인한다

## 출력

아래 모양의 JSON 하나만 낸다. 설명 문장은 붙이지 않는다.

```json
{"candidates": [{"kind": "new", "symptom": "…", "action": "…", "layer": "규칙", "token_cost": "…", "ledger_id": "", "effect": "", "evidence": [{"session": "…", "message": 3}, {"session": "…", "message": 7}]}]}
```
