# Core — 멈추는 근거

**언제 멈추고 사람에게 묻는지**(통제 영역 · 멈추는 신호 · 자동으로 하지 않는 것)를 한 곳에 모았다. `core-guardrails.md` STOP §1.4 "불확실하면 질문"이라는 일반 원칙을 재현 가능한 신호 목록으로 구체화한 것이다. `core-guardrails.md`가 "문서와 어긋나면 멈춘다"를 다룬다면, 이 파일은 그 밖의 멈춤을 다룬다 — 멈추는 이유는 표현이 모호해서가 아니라 **변경이 통제 영역에 닿기 때문**이다. 이 구분이 있어야 판정이 재현되고, 위임 영역에서는 덜 묻게 된다. 무조건적 마찰은 곧 무시당하므로, 선택적 마찰이어야 실제로 지켜진다.

## 1. 통제 영역과 위임 영역

변경이 어느 열에 속하는지로 G2 승인이 필요한지가 갈린다. 두 열에 걸치면 통제 쪽으로 본다.

| 통제 — 사람이 끊는다 (G2 승인 없이 구현하지 않는다) | 위임 — 계약과 테스트로 검증한다 (승인 없이 진행, G3에서 확인) |
|---|---|
| 도메인 규칙 · 비즈니스 흐름 · 상태 전이 | 멱등하게 테스트 가능한 컴포넌트 |
| 인증 · 과금 · 개인정보 | 표현 계층 구성 |
| 장애 복구 · 재시도 · 멱등성 | 매핑·변환 계층 |
| 외부 API 계약 · 스키마 · 마이그레이션 | 반복적인 상용구 · 문서 초안 |

변경이 왼쪽 열에 닿으면 트랙과 무관하게 **G2 승인 대상**이다. 오른쪽 열만 건드리면 G2를 짧게 지나가고 G3 검증에 무게를 둔다.

## 2. 멈추는 신호

1번 표에 걸리지 않아도 아래 하나라도 해당하면 구현 전에 확인한다.

| 신호 | 예 | 대응 |
|------|-----|------|
| 사용자가 명시하지 않은 **기본값**을 골라야 함 | TTL · 페이지 크기 · 재시도 횟수 · 타임아웃 · 파일 위치 | 후보와 권장 값을 제시하고 묻는다 |
| **열린 표현** | "알아서" · "적당히" · "최적화" · "개선해줘" · "정리해줘" | `ask` 스킬 — 라운드 방식으로 결정만 묻는다 |
| 새 파일 3개 이상 / 파일 삭제 / **의존성 추가** | | 목록을 먼저 보이고 승인 |
| 문서 2개가 다른 값을 말함 | 스펙 vs 결정 기록 | `core-guardrails.md` STOP §1 |
| **트랙이 바뀜** | B 트랙 중 계약·기술 변경이 필요해짐 → A 승격 | 멈추고 승격 여부를 묻는다 |
| **훅이 막았음** | 범위 밖 쓰기 · 마이그레이션 파일 · 위험 명령 | 아래 3절 — 우회하지 않고 보고한다 |

**의존성 사다리:** 새 의존성을 들이기 전에 표준 라이브러리 → 플랫폼 기본 기능 → 이미 설치된 의존성 → 직접 작성 순으로 먼저 밟는다. 몇 줄로 되는 일에 새 의존성을 들이지 않는다.

## 3. 자동으로 하지 않는 것

다른 규칙에 흩어져 있는 금지를 한곳에 모은 목록이다. 조건·근거는 각 SSOT가 갖는다.

| 하지 않는다 | SSOT |
|------|------|
| 커밋 · 이슈 · 브랜치 · PR 생성 | `core-workflow.md` G2·G4 |
| `[미정]` 임의 확정 · priority 라벨 부여·변경 | `core-scope.md` · `local-priority.md`(있을 때) |
| `.claude/rules/` 자동 추가 | `core-workflow.md` G4 · `retro` 스킬 |
| **훅이 막은 것을 우회** (`Bash`로 같은 일을 하는 것 포함) | 이 절 |
| **`{{작업 범위}}` 밖 파일 수정** | 이 절 · `deny-out-of-scope-write.sh`(훅 본문 상수 `SCOPE` = 이 슬롯 값) |
| "완료·통과" 선언 전에 `{{테스트 명령}}`을 실제로 돌리지 않음 | `core-workflow.md` G3 · `deny-unverified-completion.sh` |

**훅이 막은 것에 대한 승인 통로는 설정 변경이다.** 훅은 사용자의 구두 승인을 알 수 없다. 알게 만들면(환경 변수·마커 파일) 그 통로를 에이전트도 열 수 있어 결정론이 무너진다. 그래서 훅에는 "확인받았으면 통과" 같은 통로를 두지 않는다.

대신 승인은 두 가지 모양 중 하나다. 사용자가 `harness-map.md`의 `{{작업 범위}}`·플래그·슬롯 값을 바꾸고 함께 고칠 훅 상수를 바꾼다. 또는 사용자가 그 파일을 직접 고친다. 에이전트는 막힌 사실과 이유를 보고하고, 사용자가 무엇을 바꾸면 되는지 한 줄로 알려 주는 데서 멈춘다. 채팅으로 이뤄지는 G2 승인(스펙·감사 항목·원인 가설)은 이 절의 대상이 아니다.

## 금지

- 열린 요청을 스스로 해석해 구현 시작 (`ask` 없이)
- 통제 영역 변경을 "작은 수정"이라며 G2 없이 진행
- 훅 차단을 다른 도구로 우회 · 훅 스크립트·`settings.json`을 임의로 고쳐 통과
- 테스트를 돌리지 않고 완료 선언 · 돌릴 수 없으면 `report.md` "검증하지 못한 것"에 남기지 않고 넘어감
