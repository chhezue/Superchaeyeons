# Core — 범위 미확정 항목 (`[미정]`)

기획·스펙에 **아직 정해지지 않은 항목**을 다룰 때 지키는 규칙. 판단을 에이전트가 임의로 내리지 않는 것이 핵심이다. 우선순위 라벨 정책은 이 파일에 없다 — 아래 안내대로 `local-` 층이 갖는다.

**라벨·릴리즈 정책의 위치:** 이슈 우선순위 라벨(must/could 같은 MoSCoW 체계)은 프로젝트 정책이라 부품에 두지 않는다. 라벨 체계를 운영하는 프로젝트는 `local-priority.md`를 두고 `{{우선순위 SSOT}}`가 그 체계를 가리킨다 — `(없음)`이면 라벨을 논하지 않는다. 릴리즈 사실(심사 게이트·릴리즈 축·도메인 일정 용어)도 같은 방식으로 `local-release.md`에 둔다.
> 채운 예: `examples/tripfit/local-priority.md` · `examples/tripfit/tripfit-release.md`

## `[미정]` 항목 처리

기획·스펙·BR에 미확정 항목이 생기면 **해당 문서에 `[미정]` 표기만** 남긴다. 별도 중앙 트래커에 모으지 않는다.

- 기획이 확정되면 문서를 직접 amend하고 필요 시 별도 작업으로 구현한다
- 중앙 트래커가 다시 필요하다고 판단되면 그때 사용자에게 새 이슈 생성 여부를 확인한다 (`core-workflow.md` "새 이슈·새 브랜치·새 PR 생성은 항상 먼저 확인")
- 이미 구현·머지된 기능을 문서가 stale하다는 이유로 `{{제품 범위}}` Out으로 방치하지 않는다 — 실제 의존관계가 생기면 In Scope로 재승격하고 문서를 amend

**금지:** `[미정]`을 묻지 않고 임의 확정해 구현·커밋 · 중앙 `[미정]` 트래커 이슈를 새로 만들거나 되살리기 · `{{우선순위 SSOT}}`가 정한 라벨을 사용자 확인 없이 부여·변경
