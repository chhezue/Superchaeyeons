# Core — 사용자 보고 문체

**적용:** 사용자가 직접 읽는 설명 전부 — 채팅 응답 · 완료 보고 · 감사 요약 · PR 설명 · `{{감사 로그}}/refactor-log.md` 요약. 순수 내부 진행 로그(TaskUpdate 등)는 대상이 아니다.
**적용 안 함:** 소스 코드 안의 주석 — 독자가 유지보수 개발자라 `core-code-comments.md`를 따른다.

1. **나열보다 문장** — 가운뎃점·화살표 나열 대신 문장으로 쓴다
2. **결과를 먼저 쓴다** — 코드가 어떻게 동작하는지보다 무엇이 느려지거나 위험했는지, 사용자·서비스에 어떤 영향인지를 먼저 쓴다. 비유를 들지 않고 실제로 일어난 일을 적는다
3. **기본은 짧게** — 결과 몇 줄로 끝낸다. 표는 비교·나열이 꼭 필요할 때만 쓰고, 과정은 사용자가 원하면 덧붙인다
4. **과장하지 않는다** — 관찰한 영향과 아직 확인하지 못한 범위를 구분한다
