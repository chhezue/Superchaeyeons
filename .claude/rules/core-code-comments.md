# Core — 코드 주석 (언어 무관)

**적용 범위:** 소스 코드 안의 주석 — 문서화 주석·인라인 주석·필드 설명 전부.

소스 코드 안의 주석을 **어떻게 쓰는지** 정한 규칙이다. 독자는 **유지보수 개발자** — 신규 입사자, 또는 오랜만에 이 코드를 다시 여는 사람이다. 목표는 그 사람이 앞뒤 파일을 뒤지지 않고 이 파일 안에서 **실행 흐름 · 외부 시스템 연동 · 기술적 결정의 이유**를 파악하는 것이다. 언어별 문법(문서화 주석 형식, 필드 주석 위치)은 lang 팩의 "주석 규칙" 절이 정하고, 여기는 어느 언어에도 같은 **원칙**만 둔다.

**배경 (2026-09-06 개정):** 이전 규칙은 "이름이 자명하면 주석을 생략한다"는 미니멀리즘이었다. 하네스를 두 번째로 붙인 저장소의 2026-09-06 회고에서, 검색 엔진·메시지 큐·외부 모델 호출을 거치는 추천 파이프라인과 유사도·다양성 알고리즘을 그 규칙으로 읽으려니 흐름 하나를 이해하는 데 파일 여러 개를 오가야 했다는 사실이 드러났다. 그래서 방향을 바꿨다 — **이름은 무엇을 하는지를 담고, 주석은 흐름·이유·단위·제약·출처를 담는다.** 둘은 대체 관계가 아니라 분담 관계다. 코드를 그대로 우리말로 옮기는 주석(`// i를 1 증가`)은 여전히 쓰지 않는다 — 그건 이름의 일이다.

**독자가 다른 세 규칙** (같은 표가 `doc-writing.md`에도 있다 — 행을 바꾸면 두 곳을 함께 고친다):

| 대상 | 규칙 | 독자 |
|------|------|------|
| 소스 코드 주석 | **이 파일**(원칙) + lang 팩 "주석 규칙"(표기) | 유지보수 개발자 |
| 채팅 응답·완료 보고·`refactor-log.md` 요약 | `core-reporting.md` | 비전공자 |
| `.md` 문서 본문 | `doc-writing.md` | 이 저장소에서 일하는 사람·에이전트 |

## 1. 실행 흐름과 1:1로 맞춘 단계 주석

두 단계 이상으로 진행되는 함수(비즈니스 흐름·데이터 파이프라인·외부 호출 조율)는 **실제로 실행되는 줄 바로 위**에 단계 주석을 둔다 — 분기, 반복, 외부 API·DB 호출, 계산이 그 자리다. 형식은 `[N단계: 무엇을 한다]` 한 줄 + 왜 그렇게 하는지 한두 줄.

- 함수 머리의 문서화 주석에는 **요약만** 둔다. 1~4단계를 머리에 몰아 적고 본문은 비워 두지 않는다 — 독자는 코드를 따라 내려가며 읽는다
- 단계 번호와 실행 순서가 어긋나면 주석이 거짓말을 한다. 코드 순서를 바꾸면 번호도 같은 턴에 고친다
- 조기 반환·예외 분기도 단계다 — "왜 여기서 끝내는가"를 적는다

## 2. 필드·상수·의존성·DTO는 전부 해설한다

"이름만 봐도 안다"는 이유로 생략하지 않는다. 여기서 해설이란 이름이 말하지 못하는 **단위·출처·제약·목적**을 더하는 것이고, 금지하는 "코드 번역"은 실행문의 동작을 그대로 되풀이하는 것이다 — 둘은 대상이 다르다. 클래스 멤버, 상수, 주입받는 협력 객체, DTO·레코드의 각 항목마다 다음을 적는다.

| 적을 것 | 예 |
|------|-----|
| 비즈니스 목적 | 무엇을 판정·저장·전달하는 값인가 |
| 단위·범위 | ms · 초 · 점수 0~1 · 개수 |
| 기본값과 출처 | 어느 설정 파일의 어느 키에서 오는가 |
| 제약 | null 허용 여부 · 필수/선택 · 상한·하한 |
| 협력 객체의 역할 | 이 객체가 담당하는 외부 시스템·연산 |

API 스키마 설명 표기(그 언어에서 lang 팩이 정한 방식)가 있는 항목은 그 표기가 필드 설명의 SSOT다. 그 경우 주석은 표기와 **같은 문장을 반복하지 않고** 코드 독자에게만 필요한 것(내부 제약·출처)만 보탠다.

## 3. 사실만 적는다 — 주석도 문서다

주석은 `core-guardrails.md` STOP §1이 말하는 "문서"에 포함된다. 쓰기 전에 설정 파일·스키마·호출 대상의 실제 시그니처·반환값을 열어 대조한다.

- 설정 키·차원 수·타임아웃 같은 값은 실물에서 읽은 것만 적는다. 기억이나 추측으로 채우지 않는다
- 리팩터로 삭제된 로직, 아직 없는 기능을 주석에 남기지 않는다. "예정"은 TODO가 아니라 스펙에 적는다
- 코드를 바꾸면 그 줄을 설명하는 주석을 **같은 턴**에 고친다 (STOP §1.7과 같은 패턴). 코드와 어긋난 주석은 없는 주석보다 나쁘다

## 4. 이유를 평문으로 푼다

수식·알고리즘·비동기 처리·재시도 같은 기술적 선택이 나오면 "왜 이 방식인가"를 읽는 사람 관점에서 설명한다. 유사도를 거리로 바꾸는 이유, 다양성 선택 알고리즘을 쓰는 이유, 지수 백오프를 쓰는 이유 같은 것들이다.

- 전문용어는 처음 나올 때 우리말로 뜻을 풀고 쓴다 — "멱등(여러 번 호출해도 결과가 같다)"
- 화살표·기호로 상태 전이를 압축하지 않는다. "A에서 B로 바뀐다"처럼 문장으로 쓴다
- 이슈 번호·규칙 ID만 남기지 않는다 — 번호는 덧붙일 수 있지만 설명을 대체하지 못한다

## 예시

언어 무관 의사 코드다. 문법은 lang 팩을 따른다.

```
// ❌ 머리에 단계를 몰아 적고, 필드 설명은 생략
// 1. 프로필 조회 2. 검색 3. 임계치 필터
fn recommend(user):
    profile = loadProfile(user.id)
    if profile == null: return []
    results = searchClient.knn(profile.vector)
    return results.filter(r -> r.score >= threshold)

// ✅ 단계 주석은 실행 줄 바로 위에, 필드는 목적·단위·출처까지
/// 사용자 취향 벡터로 상품을 추천한다. 벡터 검색과 후처리 필터링을 조율한다.
class Recommender:
    /// 벡터 검색 인덱스를 질의하는 클라이언트. 이 클래스에서 유일하게 외부 시스템에 닿는 자리다.
    searchClient
    /// 유효 추천으로 인정하는 최소 유사도. 0~1 점수이며 설정 `recommend.threshold`에서 읽는다 (기본 0.7).
    threshold

    fn recommend(user):
        // [1단계: 취향 프로필 조회 — 없으면 조기 반환]
        // 프로필이 없는 신규 사용자는 검색을 돌려도 의미 있는 결과가 없으므로 질의 비용을 아낀다.
        profile = loadProfile(user.id)
        if profile == null:
            return []

        // [2단계: 코사인 유사도 기반 최근접 이웃 검색]
        // 인덱스의 벡터 차원(1536)은 프로필 벡터와 같아야 한다 — 인덱스 매핑 파일에서 확인한 값.
        results = searchClient.knn(profile.vector)

        // [3단계: 임계치 미달 제거]
        // 유사도가 낮은 항목까지 내려보내면 추천 신뢰도가 떨어진다. 정렬은 검색 결과 순서를 그대로 쓴다.
        return results.filter(r -> r.score >= threshold)
```

## 검증

문체는 exit code로 판정할 수 없어 **advisory**다. 코드 리뷰(`code-review` · 스택 리뷰어)가 다음을 본다.

- 단계 주석 번호가 실행 순서와 일치하는가
- 주석에 적힌 설정 키·단위·차원 값이 실물과 같은가 (리뷰어가 파일을 열어 대조)
- 필드·의존성 중 해설이 없는 것이 있는가
- 코드를 그대로 번역한 주석, 상단에 몰아 적은 단계 요약, 설명 없는 이슈 번호가 남았는가

## 금지

- "이름이 자명하다"는 이유로 필드·상수·의존성·DTO 해설 생략 (해설 = 단위·출처·제약·목적. 코드 동작 되풀이가 아니다)
- 함수 머리에 단계를 몰아 적고 본문에는 단계 주석을 두지 않음
- 코드를 우리말로 옮긴 주석 (`// 목록을 순회한다`)
- 실물과 대조하지 않은 값·삭제된 로직·상상한 동작 서술
- 화살표·기호 압축, 설명 없는 영어 전문용어, 이슈 번호만 남기기
- 코드를 바꾸고 그 줄의 주석은 다음 턴으로 미루기
