# Core — 가드레일 (⛔ STOP)

구현·기본값 변경·커밋 **전에 멈춰야 하는 것**만 모았다. 여기 걸리면 다른 규칙·워크플로보다 먼저 중단하고 사용자에게 묻는다. 작업 순서는 `core-workflow.md`, 그 밖의 멈추는 신호는 `core-gates.md`가 갖는다.

**플래그:** `[플래그: X]` 절의 적용 여부는 `harness-map.md` 능력 플래그 표가 정한다. 꺼도 절을 지우지 않는다 — 지우면 부품이 갈라져 이후 개선을 함께 받을 수 없다.

## §1. 문서·구현 정합

1. **문서 vs 구현** — `{{스펙 저장소}}`(Approved)·`{{결정 기록}}`(확정)·`{{제품 범위}}`·`{{아키텍처 개요}}`·`{{배포 SSOT}}`와 다른 TTL·API 계약·enum·한도·env 이름·패키지 경로를 조용히 맞추지 않는다
2. **문서 vs 문서** — 두 문서(스펙·PRD·결정 기록·`.env.example` 등)가 다른 값·용어·경로를 말하면 한쪽을 고르지 말고 충돌을 목록으로 보여 확인받는다
3. **임의 개선 금지** — "더 나은 기본값"·"업계 일반값"·"코드가 간단해짐"만으로 문서와 다른 수치·구조를 쓰지 않는다. 바꾸려면 문서 amend 또는 사용자 명시 승인
4. **불확실하면 질문** — 가정을 숨기지 않는다. 질문 없이 진행한 선택은 잘못된 작업이다
5. **"미구현"이라고 단정하기 전에 코드부터** — 스펙 체크박스·"미구현" 같은 서술은 merge 뒤 동기화가 빠지면 틀린다. 진입점·테스트를 직접 grep/Read하고, 이슈 상태는 트래커에서 본다
6. **[플래그: 생성 문서 검증]** "생성 문서에 이미 있다"고 답하기 전에 생성물이나 `{{API 문서}}`를 실제로 연다 — 소스에 설명 표기가 있어도 스키마가 통째로 빠질 수 있다
7. **계약에 닿는 변경은 같은 턴에 끝낸다** — 코드와 계약·문서·생성물(enum·스펙 에러 표·응답 스키마·주석)이 함께 바뀌어야 하면 같은 PR·같은 턴에 고친다. "다음 커밋에" 금지
8. **`[미정]`은 표기만** — 기획·스펙의 미확정 항목은 그 문서에 `[미정]`만 남기고 임의로 확정해 구현·커밋하지 않는다. 중앙 트래커 이슈를 만들거나 되살리지 않는다. 확정되면 문서를 amend하고 별도 작업으로 구현한다. 우선순위 라벨·릴리즈 사실은 `local-priority.md`·`local-release.md`(있을 때만)가 갖고, 라벨은 사용자 확인 없이 붙이거나 바꾸지 않는다

## §2. 레거시 즉시 삭제 — 호환 레이어 금지

현행 Approved 스펙·BR·decisions·구현 계약과 다른 코드·경로·문서를 "호환용"으로 남기지 않는다. 운영 데이터가 있는 프로젝트의 구 스키마·구 클라/DB 호환은 그 프로젝트의 마이그레이션 정책을 따른다.

- **같은 커밋·PR·턴에 지운다.** "다음 커밋에 정리"·"일단 새 경로만 추가" 금지
- **교체 = 구경로 삭제:** 이번 변경이 대체한 것은 요청 범위다. 무관한 기존 dead code만 언급으로 끝낸다
- 삭제 대상 목록은 `verify-work` 5단계

## §3. 보안·아키텍처 변경 — 현재동작 요약 갱신

인증·세션·시크릿·결제·개인정보 처리처럼 "바뀐 걸 사용자가 한참 뒤에야 알면 곤란한" 로직을 바꾸면, 같은 턴에 `{{현재동작 요약}}`의 해당 절을 다른 문서 없이 읽히는 쉬운 말로 고친다(없던 주제면 절을 추가). 스펙에만 적고 넘어가거나 "사소한 변경"이라며 생략하지 않는다.

**훅이 못 보는 것:** API 키를 파일·로그에 쓰지 않는다. 파괴 명령은 `deny-dangerous-bash.sh`가 막는다.
