# 설치 후 테스트와 작업당 토큰 측정

새 프로젝트의 전체 테스트가 현재 설치본을 실행하도록 고쳤다. 오타처럼 영향이 좁은 변경은 관련 파일부터 보고, 외부 계약이나 여러 구성 요소의 동작이 바뀔 때 독립 리뷰를 받도록 작업 절차를 바꿨다. 비교 기준은 커밋 `2d58b2a`다.

## 두 종류의 측정

| 세션 시작 훅의 추가 지시 | 이전 | 수정 후 | 변화 |
|---|---:|---:|---:|
| Claude | 18,206 B | 15,387 B | −15.5% |
| Codex | 22,549 B | 18,683 B | −17.1% |

두 버전의 등록된 시작 훅을 같은 프로젝트 설정과 빈 회고 상태에서 실행했다. 임시 설치 경로 길이에 따라 결과가 달라져 표에서는 경로를 `/plugin`으로 통일했다. 최종 검사에서 정규화한 합계가 Claude 16,000바이트, Codex 20,000바이트를 넘으면 실패한다. 모델이 받는 다른 지침과 도구 출력은 이 표에 포함되지 않는다. [시작 훅 측정기](../../scripts/measure-startup-context.py)

| 실제 모델 과제 | 이전 성공 작업당 토큰 | 수정 후 | 변화 | 성공 |
|---|---:|---:|---:|---:|
| 문구 오타 수정 | 131,510 | 118,094 | −10.2% | 양쪽 3/3 |
| 공개 API 필드 변경 | 260,484 | 266,052 | +2.1% | 양쪽 3/3 |

이 실험은 작업 순서 규칙 한 파일을 바꿨을 때의 차이를 본다. 매회 같은 소스와 문서가 있는 임시 프로젝트를 만들고, 이전 또는 새 규칙을 `AGENTS.md`로 제공했다. 시작 훅은 등록 파일에 따라 별도로 실행했고, 설치 후 완료 판정은 소비 프로젝트에서 두 호스트의 이벤트를 재생해 확인했다. 모델 실험에서는 외부 서비스, 실제 커밋, 배포를 요청하지 않았다.

모델은 `gpt-6.2-sol`, 실행기는 Codex CLI(명령줄 도구) `0.171.0-alpha.13`이다. 작업별로 각 조건을 3회씩 실행했고 2회차는 순서를 뒤집었다. 문구 과제는 한 세션에서 수정했고, API 과제는 제안과 승인 뒤 구현을 두 세션으로 나눴다. 첫 세션 뒤 API 소스가 그대로이고 제안에 새 필드가 있는지 검사한 후, 모든 실행에 같은 승인 답변을 전달했다. 외부 채점 코드는 최종 응답의 필드·값과 표시 문구를 검사했다. 12개 과제가 모두 조건을 통과했다.

성공 작업당 토큰은 해당 조건의 모든 세션에서 실행기가 보고한 입력과 출력의 합을 성공 건수로 나눈 값이다. 캐시 입력은 입력에 이미 포함된다. 실패한 모델 선택 시도는 과제 실행 전에 거부되어 표에서 제외했다. 실제 청구액, 장기 프로젝트의 리뷰 품질은 측정하지 않았다.

## 회차별 사용량

| 과제 | 회차 | 이전 입력 | 이전 캐시 입력 | 이전 출력 | 수정 후 입력 | 수정 후 캐시 입력 | 수정 후 출력 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 문구 | 1 | 142,977 | 112,768 | 377 | 110,661 | 96,256 | 207 |
| 문구 | 2 | 114,404 | 98,816 | 402 | 111,330 | 96,512 | 363 |
| 문구 | 3 | 136,024 | 108,672 | 345 | 131,428 | 106,112 | 294 |
| API | 1 | 290,027 | 256,256 | 1,030 | 216,515 | 188,160 | 796 |
| API | 2 | 267,994 | 217,216 | 1,202 | 253,255 | 208,512 | 956 |

문구 과제는 세 회차 모두 토큰이 줄었다. API 과제는 1·2회차에 줄고 3회차에 늘었다. 두 과제를 같은 비중으로 합친 평균은 2.0% 줄었지만, 이 표본으로 평소 작업의 절감률을 예측할 수는 없다.

## 재실행과 설치 검증

아래 스크립트는 요청할 때만 모델을 호출한다. 저장소의 표준 검사에는 모델 없이 실행하는 시작 훅 분량과 설치 회귀 검사만 포함된다. [모델 평가 실행기](../../scripts/evaluate-task-routing.py)

```bash
git show 2d58b2a:plugin/rules/core-workflow.md > /tmp/superchaeyeons-before-task-steps.md
python3 -I scripts/evaluate-task-routing.py --model gpt-6.2-sol --before /tmp/superchaeyeons-before-task-steps.md
```

설치 회귀 검사는 새 소비 프로젝트에 실제 생성기를 적용한다. 프로젝트에는 테스트 설정만 두고, 세션에 표시된 명령으로 전체 테스트를 실행한다. 공백·따옴표가 있는 경로로 설치본을 이동한 뒤에도 두 호스트 모두 마지막 편집 이후의 실패와 성공을 구분하는지 확인한다. 문서 검사는 Git이 제공하는 원래 파일명을 사용해 한글·공백·줄바꿈이 있는 파일도 검사한다. [설치 회귀 검사](../../scripts/test-codex-context.sh) · [문서 검사 회귀 사례](../../scripts/hook-cases.txt)

기존 설치에서 바뀐 스킬 호출명과 규칙 경로는 갱신 안내에 정리했다. [이름 변경표](../../README.md#github-배포와-업데이트)
