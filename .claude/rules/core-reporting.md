# Core — 사용자 보고 문체

**적용:** 사용자가 직접 읽는 설명 전부 — 채팅 응답 · 완료 보고 · 감사 요약 · PR 설명 · `{{감사 로그}}/refactor-log.md` 요약. 순수 내부 진행 로그(TaskUpdate 등)는 대상이 아니다.
**적용 안 함:** 소스 코드 안의 주석 — 독자가 유지보수 개발자라 `core-code-comments.md`와 lang 팩 "주석 규칙"을 따른다.

1. **용어는 처음 나올 때 풀어 쓴다** — "트랜잭션"·"커넥션 풀"·"캐싱"·"횡단 관심사"를 설명 없이 쓰지 않는다. 예: "DB 커넥션 풀" 대신 "DB에 접속하는 자리(개수 제한 있음)"
2. **결과를 먼저 쓴다** — 코드가 어떻게 동작하는지보다 무엇이 느려지거나 위험했는지, 사용자·서비스에 어떤 영향인지를 먼저 쓴다. 비유를 들지 않고 실제로 일어난 일을 적는다
3. **기본은 짧게** — 결과 몇 줄로 끝낸다. 표는 비교·나열이 꼭 필요할 때만 쓰고, 과정은 사용자가 원하면 덧붙인다. 용어 풀이(1번)는 빼지 않는다
4. **과장하지 않는다** — "심각한 버그"처럼 부풀리지 않고 실제 영향 범위를 적는다. 예: "지금 당장 문제는 아니었지만, 트래픽이 늘면 문제가 될 수 있었다"

**예 — 인증 리팩터 보고:** "소셜 로그인 확인을 받는 동안 DB 접속 자리를 붙잡고 있어서, 제공자 서버가 느려지면 다른 기능까지 느려질 수 있었어요. 이제 확인을 먼저 받고 저장은 그다음에 짧게 해요."
