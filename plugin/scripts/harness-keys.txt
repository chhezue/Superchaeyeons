# 프로젝트 설정 파일(.claude/harness.conf)의 키 목록 — 키<TAB>종류<TAB>이름<TAB>뜻. 훅·검사기·init-harness가 읽는 SSOT다.
# 종류: slot = 규칙이 {{이름}}으로 부르는 경로·명령·형식 · flag = 규칙의 [플래그: 이름] 절 적용 여부(1/0) ·
#       hook = 훅이 판정에 쓰는 값 · info = 설명용. 값 규칙(빈칸·(없음))과 고칠 때의 규칙은 skills/init-harness/references/harness-conf.md
AXES	info	축	lang·shape·deploy·stage — 붙이는 시점에 실측한 값. 규칙은 축을 직접 부르지 않는다
DOC_ROOT	slot	{{문서 루트}}	함께 배달되는 문서 경로의 기준 폴더 — 회고 장부·글 다듬기 대상도 이 값을 쓴다
SCOPE	slot	{{작업 범위}}	쓰기 범위. `.`이면 저장소 전체라 범위 검사를 하지 않는다 — deny-out-of-scope-write.sh가 읽는다
GIT_CONVENTION	slot	{{Git 컨벤션 SSOT}}	Git 형식 문서. (없음)이면 core-workflow G2·G4가 SSOT
SPEC_DIR	slot	{{스펙 저장소}}	스펙 문서 폴더
CURRENT_BEHAVIOR	slot	{{현재동작 요약}}	보안·아키텍처 성격 변경 때 쉬운 말로 갱신할 문서
PRIORITY_SSOT	slot	{{우선순위 SSOT}}	이슈 우선순위·Milestone의 SSOT
ARCH_OVERVIEW	slot	{{아키텍처 개요}}	아키텍처 개요 문서
SCHEMA_SSOT	slot	{{스키마 SSOT}}	DB 스키마의 SSOT
API_RESPONSE	slot	{{API 응답 규격}}	API 응답 규격 문서
API_DOCS	slot	{{API 문서}}	생성 API 문서
PRODUCT_SCOPE	slot	{{제품 범위}}	제품 범위 문서
CLIENT_ASSUMPTIONS	slot	{{클라이언트 전제}}	클라이언트 전제 문서
GLOSSARY	slot	{{용어집}}	도메인 용어집
DECISIONS_DIR	slot	{{결정 기록}}	결정 기록(ADR) 폴더
AUDIT_DIR	slot	{{감사 로그}}	감사·리팩터 기록 폴더
DEPLOY_SSOT	slot	{{배포 SSOT}}	배포 SSOT 문서
TEST_CMD	slot	{{테스트 명령}}	전체 테스트 명령. 하네스 기본은 플러그인 scripts/dev.sh test — deny-unverified-completion.sh가 이 명령의 실행 기록을 본다
BUILD_CMD	slot	{{빌드 명령}}	빌드 명령 (보통 scripts/dev.sh build)
FORMAT_CMD	slot	{{포맷 명령}}	포맷 명령 (보통 scripts/dev.sh fmt — 첫 단어가 프로젝트에 없고 플러그인에 있으면 플러그인 쪽). 비어 있거나 (없음)이면 포맷하지 않는다
DEPS_CMD	slot	{{의존성 조회}}	의존성 조회 명령
BRANCH_FORMAT	slot	{{브랜치명 형식}}	브랜치 이름 형식
COMMIT_FORMAT	slot	{{커밋 메시지 형식}}	커밋 메시지 형식(사람이 읽는 꼴)
BASE_BRANCH	slot	{{기본 브랜치}}	PR base 브랜치
MERGE_METHOD	slot	{{머지 방식}}	PR 머지 방식
ISSUE_LINK	slot	{{이슈 연결}}	이슈 트래커와 연결 표기 — 안내는 local-track-issues 스킬
FLAG_GENERATED_DOCS	flag	생성 문서 검증	1이면 core-guardrails §1.6 적용
HARNESS_SELF_EDIT	flag	하네스 자기 수정	1이면 에이전트가 하네스 훅·설정을 고칠 수 있다(하네스 원본 저장소만). 0이면 deny-out-of-scope-write.sh가 막는다
POLISH_ENABLED	flag	Gemini 다듬기	1이면 스킬이 사람용 문서·메시지를 polish-with-gemini.sh로 다듬는다
COMMIT_RE	hook	커밋 메시지 정규식	{{커밋 메시지 형식}}을 판정하는 확장 정규식(ERE). 비어 있으면 형식을 검사하지 않는다
COMMIT_CHECK	hook	커밋 전 검사 명령	승인 창을 띄우기 전에 돌릴 검사 명령. 실패하면 커밋을 막는다. 비어 있으면 돌리지 않는다. 프로젝트 폴더에서 돌고, 첫 단어가 프로젝트에 없는 상대 경로인데 플러그인 폴더에 있으면 플러그인 쪽을 부른다(예: scripts/dev.sh test)
FORMAT_PATHS	hook	포맷 대상 경로	FORMAT_CMD를 돌릴 파일 glob(공백 구분)
CONTRACT_PATHS	hook	API 계약 파일	커밋 승인 창이 이유에 적을 계약 파일 glob(공백 구분)
DEPS_FILES	hook	의존성 선언 파일	고치면 승인 창을 띄울 빌드 선언 파일 glob(공백 구분)
DEPS_ADD_CMD	hook	의존성 추가 명령	실행하면 승인 창을 띄울 설치 명령 접두사(|로 구분)
ASK_PATHS	hook	민감한 경로	쓰면 승인 창을 띄울 glob(공백 구분). 비어 있으면 묻지 않는다
ASK_COMMIT	hook	승인 창 — 커밋·원격 반영	1이면 git commit·push·gh pr create·merge에 승인 창
ASK_DELETE	hook	승인 창 — 삭제	1이면 추적 중인 파일 삭제에 승인 창
ASK_DEPS	hook	승인 창 — 의존성 추가	1이면 DEPS_FILES 수정·DEPS_ADD_CMD 실행에 승인 창
ASK_SENSITIVE	hook	승인 창 — 민감한 경로	1이면 ASK_PATHS 쓰기에 승인 창
ASK_SPEC	hook	승인 창 — 스펙 승인·[미정] 확정	1이면 스펙·결정 기록의 Approved 전환·[미정] 감소에 승인 창
BLOCK_FORCE_PUSH	hook	막기 — 원격 이력 덮어쓰기	1이면 force push를 훅이 막는다(0이면 permissions.deny에 맡긴다)
BLOCK_BULK_DELETE	hook	막기 — 파일 대량 삭제	1이면 rm -rf·find -delete를 훅이 막는다(0이어도 루트·홈 삭제는 막는다)
BLOCK_GIT_DISCARD	hook	막기 — git 이력·작업 트리 버리기	1이면 reset --hard·clean -f·branch -D를 막는다
BLOCK_CHECK_BYPASS	hook	막기 — 검사 우회·시크릿 커밋	1이면 commit --no-verify·.env add를 막는다
BLOCK_DATA_DELETE	hook	막기 — 데이터 저장소 삭제	1이면 SQL DROP·compose down -v를 막는다
BLOCK_SYSTEM	hook	막기 — 시스템 위험	1이면 curl|sh·chmod -R 777·dd of=/dev/를 막는다
AUTO_ANALYZE	hook	회고 자동 분석	1이면 마지막 분석에서 7일이 지났을 때 세션 시작 알림 훅이 분석을 뒤에서 띄운다
