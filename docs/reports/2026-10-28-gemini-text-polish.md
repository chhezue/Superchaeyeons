# Gemini 글 다듬기 — 작업 보고서

사람에게 남는 글(문서, 커밋 메시지, PR·이슈 글)을 Gemini가 한 번 더 다듬고 Claude가 검수하는 단계를 [스펙](../specs/cross-cutting/gemini-text-polish.md)대로 구현했다. 기계 검증은 모두 통과했으며, 실제 Gemini 키로 돌려보는 확인은 아직 하지 않았다.

## 무엇을 했나

- `scripts/polish-with-gemini.sh`를 신설했다. 문서 다듬기(`docs`), 기준판 기록(`done`), 메시지 다듬기(`message`), 다듬지 않은 문서 찾기(`unpolished --staged`), 켜짐 확인(`enabled`) 기능을 담당한다
- `.claude/hooks/auto-polish-message.sh`를 신설하고 `settings.json`에 등록했다. 커밋·트래커 명령의 첫 실행을 멈추고 다듬은 메시지를 돌려주며, 다시 실행하면 승인 창을 띄운다. 트래커 명령은 상수 `TRACKER_COMMANDS`로 분리했다
- 스킬 5개에 다듬기 단계와 플래그 질문을 추가했다: `write-spec`, `refactor-safely`, `verify-work`, `improve-harness`, `init-harness`
- `harness-map.md`에 "Gemini 다듬기" 플래그(☑)를 추가했다. `.claude/rules/README.md`에는 목록, 훅 상수 짝, `auto-` 규약 예외를 기록했다
- `scripts/check-portability.sh`는 `TRACKER_COMMANDS` 대입 줄을 원본 저장소에서도 값 자리로 판단한다. `scripts/test-hooks.sh`에는 `;env:`(환경 변수 주입)와 `;cp:`(견본 복사)를 추가했다
- 케이스 63건과 견본(`scripts/hook-fixtures/polish/`)을 추가했다
- 문서도 수정했다: `docs/harness/README.md` "지금의 실제 동작", 산출물 등록부, 플러그인 배달 스펙의 훅·도구 목록, `AGENTS.md`, `.gitignore`(`.claude/polish/`)

## 결정

| 결정 | 근거 | 대안 |
|------|------|------|
| 문서는 작성이 끝나는 시점(승인 요청 직전·완료 보고 직전·회고 기록 직후)에 스킬 단계로 다듬는다 | 사람이 처음 읽기 직전이고 다른 편집이 없어 충돌이 없다 | 턴 끝 훅(대기), 백그라운드(충돌·경고 안 보임), 주 1회(최대 일주일 지연) — 기각 |

| 트래커 명령을 훅 상수로 뺐다 | core 훅에 GitHub 전용 명령을 쓰면 이식성 검사(C1)에 걸린다 | 커밋만 다듬기 |

## 검증하지 못한 것

| 무엇 | 왜 못 했나 | 누가·언제 확인하나 |
|------|-----------|-------------------|
| 실제 Gemini 호출과 다듬은 글의 품질 | 이 세션에 키가 없다 | 사용자 — 키를 넣은 뒤 이 저장소 문서 하나와 커밋 하나로 |
| 데스크톱 앱 세션의 훅이 환경 변수를 받는지, 키체인으로 읽히는지 | 키가 없다 | 같은 때 |
| `PreToolUse` 이유 글의 길이 상한 | 공식 문서에서 확인하지 못했다 | 긴 메시지로 실제 확인할 때(스펙 리스크 6) |
| 시간 초과 동작 | `file://` 가짜 응답으로는 지연을 만들 수 없다 | 코드로만 확인 — 알람과 프로세스 그룹 종료 |
| python3가 없을 때 | 실행기가 PATH를 바꾸는 내장 케이스를 `deny-*` 훅에만 돌린다 | 코드로만 확인 |

## 남은 것

- **켜짐 값이 복사본에 그대로 따라간다.** 이 저장소의 `POLISH_ENABLED`가 `1`이라 `init-harness` 없이 복사하면 켜진 채 시작한다. 그 컴퓨터에 키가 있으면 그 프로젝트 글이 Google로 나간다. "하네스 자기 수정"과 같은 구조지만 외부 전송이라 더 위험하다 → 배달 기본값을 `0`으로 두고 이 저장소 값만 다른 자리에 두는 방법을 정해야 한다
- **트래커가 프로젝트마다 다르다.** 메시지 훅은 `--title`·`--body` 옵션을 쓰는 CLI만 알아듣고, MCP로 이슈를 만드는 트래커(Notion·Linear·Jira MCP 등)는 다듬지 못한다 → 트래커 추상화 방식은 조사를 마쳤고 결정을 기다리고 있다
- 백틱 4개 이상의 펜스는 고쳤지만, 들여쓰기로 만든 코드 블록(공백 4칸)은 여전히 문단으로 본다
